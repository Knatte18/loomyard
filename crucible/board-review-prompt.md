## Why this round exists — read this first
Commit `1fe3d2d3` ("board: move storage to weft:main") just replaced `board`'s entire storage model: `_board` used to be its own separate cloned git repo (`hubgeometry.BoardDir(hub)`, cloned from a configurable URL, defaulting to `<weft>.wiki.git`); it is now a **second worktree of the weft repo itself**, checked out on the host's own **unsuffixed** default branch (`weft:main` in the common case — never a `<branch>-weft`-suffixed pairing, which is reserved for every OTHER weft worktree). This is a from-scratch architectural change, not a refactor of existing plumbing — treat this as a genuinely new round 1, not a continuation of any prior board review. Specific new pieces this round must scrutinize hardest:
- `internal/fabricengine/boardweft.go`'s `ensureBoardWorktree` — adopts `hostBranch` as a `git worktree add` if it already exists locally (the ordinary re-clone/existing-remote case), or creates it as `git worktree add --orphan -b <hostBranch>` if the weft remote was genuinely empty (a brand-new project). Both paths are invoked from `fabricengine.CloneHub` (now two URLs, not three — `boardURL`/`deriveBoardURL` are gone entirely).
- `internal/fabricengine/weftgit.go`'s new package-level `CommitWeftAt`/`PushWeftAt` — a **warp-untethered** commit/push pair used only by `_board`'s `weft:main` checkout, which (unlike every other weft worktree) has no corresponding warp branch to trailer a commit against or record a correspondence for. `CommitWeftAt` wraps `gitrepo.StageAllAndCommit` directly (wildcard `git add -A`, no pathspec filtering, no lock of its own — see its doc comment for why it deliberately skips `ensureWeftLockDir`'s lock). This is a **new, narrower contract** than the well-tested `Fabric.CommitWeft`/`PushWeft` pair (positive-pathspec-required, Warp-SHA trailer, correspondence recording) — do not assume test coverage or invariants proven for the old pair transfer to this one.
- `internal/boardengine/sync.go` now calls `fabricengine.CommitWeftAt`/`PushWeftAt` instead of a `gitrepo.Repo` directly. `cmd/lyx/boardguard_test.go` is a NEW machine-checked guard (AST import scan + same-line exec.Command/"git" scan) that fails the build if `internal/boardengine`'s production code ever imports `gitrepo`/`gitexec` or shells out to `git` directly — confirm this guard's own logic is sound (not just that it currently passes).
- `CONSTRAINTS.md`'s Weft Git Invariant gained a **"Board carve-out"**: board is the one exception to the rule that weft commits are timed by a loop owner (loom/perch) — any LLM session, in any worktree, may trigger a board write at any time. Module ownership (all weft git flows through `fabricengine`) still applies without exception; only the timing-control half is carved out. Confirm the code actually matches this stated carve-out (e.g. nothing re-introduces a timing gate board doesn't need, and nothing lets an agent bypass the module-ownership half).
