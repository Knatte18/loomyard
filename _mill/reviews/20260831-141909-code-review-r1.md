**Location:** `internal/shell/shell_test.go:11`
**Issue:** The measurement gate (batch 2) recorded "no candidate accepted" in `doc.go`, so batch 3 took Branch C, which requires "Make no change to `internal/shell/shell_test.go`... in this branch" (03-repaint-entry.md, card 13). `internal/shell/shell.go`'s `Shell` interface carries only the original five members (`Quote`/`Invoke`/`ReadFile`/`WithEnv`/`Touch`) — `ForEachLine`/`LineVarRef` were never added — yet `shell_test.go:11` reads "Compile-time assertions that both dialects satisfy the **widened** Shell interface." ### [NIT:design] Criterion isolation relies on a bare zero-value `testing.T`
**Location:** `internal/reedcli/smoke_dotfill_measure_test.go:222-241` (`isolatedCriterionResult`)
**Issue:** To record a candidate's pass/fail per criterion without failing the parent subtest, the helper constructs `&testing.T{}` directly and calls `Fatalf`-style helpers on it from a goroutine, relying on undocumented zero-value behavior of the `testing` package (no `t.Run`/registration) rather than any exported mechanism.
**Fix:** No action required now, but if a future Go `testing` release starts relying on additional non-zero internal state, this pattern will need re-verification; consider isolating via a plain error-returning check instead of a scratch `*testing.T` for long-term robustness.
