## Findings

### [BLOCKING] doc.go's SnapshotWarpSHA references go stale, no card fixes them
**Location:** batch 5 / card 19 (Unexport SnapshotWarpSHA)
**Issue:** `internal/fabricengine/doc.go` names `Fabric.SnapshotWarpSHA` (exported, capitalized) six times (lines 84, 86, 90, 92, 102, 104), describing it as "the sole exported entry point." Card 19 unexports it to `snapshotWarpSHA` but its Edits are only `snapshot.go` + `commit_integration_test.go`; no card touches `doc.go` for this rename.
**Fix:** Add `doc.go` to card 19's (or a new card's) Edits and update all six mentions to the new casing/exported-status.

### [BLOCKING] SyncWeft/RevertWithWeft doc-comment cascade misses 3+ files
**Location:** batch 5 / card 20 (Doc-comment cascade cleanup in fabricengine)
**Issue:** Card 20 self-instructs "Grep fabricengine and boardengine for any remaining SyncWeft/RevertWithWeft mention and fix it," but its Edits list (doc.go, index.go, topology.go, fabric.go, board.go) omits three files confirmed (via grep) to carry live `RevertWithWeft` mentions: `checkout_index_refresh_test.go:9`, `commit_partial_integration_test.go:26` (names the about-to-be-deleted `TestRevertWithWeft_WeftResetFailure_RollsWarpBack`), and `revert_test.go:2` — the latter directly contradicted by card 18's own "revert_test.go … stays UNCHANGED." Separately, `diff.go`'s file header and `ChangeEntry` doc comment (both context-only, never in any card's Edits) still describe `StatusWeft` as a live surface after card 24 deletes it.
**Fix:** Add the three test files (and diff.go, cross-referenced with card 24) to Edits; drop or reconcile the "stays UNCHANGED" instruction for revert_test.go.

### [BLOCKING] CONSTRAINTS.md's own Fabric Git Invariant text goes stale mid-task
**Location:** batch 2 / card 12 and batch 3 / card 14 (both edit CONSTRAINTS.md's Fabric Git Invariant section)
**Issue:** The "Orchestration, not agent" bullet (line 92) reads "the engine in-process (`fabricengine`'s `SyncWeft`/`CommitWeft`)" — `SyncWeft` is deleted in batch 5 and `CommitWeft` is unexported to `commitWeft` in batch 6. Neither card 12 nor card 14 (the two cards that already touch this exact section for other bullets) revises this sentence, so CONSTRAINTS.md — explicitly "authoritative" — ships referencing a deleted method as current.
**Fix:** Add a requirement to card 26 (or a new card) to update this bullet's method names/casing.

### [BLOCKING] No card adds regression coverage for the new both-sides Clean check
**Location:** batch 4 / card 16 (rename HostClean→Clean, extend to warp+weft)
**Issue:** Card 16 introduces a genuinely new failure mode (a dirty weft worktree now fails `Clean`) plus a new existence-guard, but its Edits are only `hostclean.go`/`preflight.go` — `preflight_integration_test.go` is Context-only. The batch's own "Batch Tests" prose says to extend coverage only "if needed," with no card assigned to do it. Existing tests (`TestPreflight_HostDirty`, `TestPreflight_WeftWorktreeRemoved`) never write dirty content into the weft worktree, so the new weft-dirty branch ships with zero positive test.
**Fix:** Add `preflight_integration_test.go` to card 16's Edits with an explicit requirement to add a dirty-weft-only case (and ideally a both-dirty case).
