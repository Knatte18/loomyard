## Fixed

- `20260829-111436-plan-review-r1.md` — "[BLOCKING:design] fetch()'s root/child kind not bound to call sites".
  Batch 2, card 5 now binds the two values explicitly: `root` is passed by exactly the two fetches addressing the walk's seed item (its `rec` fetch of `BASE_REF` and the `nonrec` re-fetch of the same `BASE_REF`), `child` by every other fetch the queue drains.
  Also states why the binding matters — only a `root` fetch can carry the caller's `path`, which is what makes the scoped-versus-unscoped 404 branch well defined.
- `20260829-111436-plan-review-r1.md` — "[BLOCKING:design] path-validation loop is locale-dependent for multi-byte characters".
  Replaced the character-by-character walk with a locale-independent pattern substitution, `"${path//[A-Za-z0-9._\/-]/}"`, reporting whatever remains.
  Chose this over the reviewer's other option (pinning `LC_ALL=C.UTF-8`) because `C.UTF-8` is a glibc locale that is not present on macOS or the BSDs, so pinning it would trade a locale-dependent bug for a platform-dependent one on a harness whose asserted envelope explicitly includes macOS.
  The substitution needs no locale guarantee at all: the accepted set is pure ASCII and a UTF-8 continuation byte is never in it, so no multi-byte sequence can be split.
  The message now names the offending character set rather than a first offender, since no first-offender extraction is byte-safe without re-introducing indexing.
  Batch 1, card 4, test 17 updated to assert the three expected offenders by value, calling out `ï` specifically as the assertion that pins the mechanism.
- `20260829-111436-plan-review-r1.md` — "[NIT:consistency] harness assertion wording drifts from the fixed 403 stderr string".
  Test 13 now asserts the literal substring `rate limited`.
  Extended the same fix to test 12, which had the identical defect (`mentions authentication` against a fixed message reading `not authenticated`) and would have drifted the same way;
  the reviewer named only the 403 case, but leaving the adjacent instance would reintroduce the finding on the next round.
  Added a clause stating the general rule so a later test does not paraphrase again.
- `20260829-111436-plan-review-r1.md` — "[NIT:consistency] generic fallback error message can exceed the documented \"one stderr line\" contract".
  Card 5's generic branch now collapses the body to one physical line with `"${body//$'\n'/ }"` before embedding it.
  Chose fixing the script over softening `SKILL.md`'s wording: the one-line promise is what lets a caller treat stderr as a single diagnostic, and it is cheaper to keep than to qualify.
