## Findings

### [BLOCKING] Card 21 uses builtins() without registry.go in Context
**Location:** Batch 5 (ensure-server-native), Card 21
**Issue:** Requirements call `ensureNative(ctx, "go", builtins()["go"], repoRoot(t), ...)`; `builtins()` is defined in `registry.go`, which is not in Card 21's `Context:` (only refs_integration_test.go, toolchain_integration_test.go, ensureserver.go are listed).
**Fix:** Add `internal/codeintelengine/registry.go` to Card 21's `Context:`.

### [BLOCKING] Card 43 misses two more stale doc.go claims of its own kind
**Location:** Batch 11 (finalize-docs-and-invariants), Card 43
**Issue:** Card 43 explicitly fixes two named false claims but misses two more of the identical kind already in `doc.go`: "The generalized LSP client" section's "speaks exactly six methods... initialize, initialized, textDocument/references, workspace/symbol, shutdown, exit" (now seven, missing textDocument/definition added in batch 8), and "The typed error vocabulary" section's "internal/codeintelcli maps every one of these... uniformly to output.Err(err.Error()) with exit 1 — no error needs a distinct exit code" (false once ErrAmbiguousSymbol gets exit 2 in batch 9).
**Fix:** Add both corrections to Card 43's six-item enumerated list.

### [NIT] Batch 4's depends-on:[1] is unexplained by its own cards
**Location:** 00-overview.md prose vs. Batch 4 (daemon-state-and-locking)
**Issue:** The overview says batch 4 "needs... batch 2's now-allowlisted internal/lock import," but batch 4's cards (12-16) never import internal/lock or consume hubgeometry's new accessor — that consumption belongs to batch 6, not batch 4; depends-on:[1] has no visible card-level justification either.
**Fix:** Correct the overview's rationale (the real batch-2 link is the shared CONSTRAINTS.md/leaf_enforcement_test.go edit ordering) and re-justify or drop the batch-1 edge.

### [NIT] Card 33 leaves a stale comment in refsCommand
**Location:** Batch 9 (cli-definition-and-symbol), Card 33
**Issue:** The existing inline comment "no error needs a distinct exit code, so this mapping stays uniform" in `refsCommand` isn't flagged for removal, though it becomes false the moment ambiguous symbols get exit code 2.
**Fix:** Add removing/updating that comment to Card 33's requirements.

### [NIT] ensureSupervised's loser retry path has no backoff on one branch
**Location:** Batch 6 (ensure-server-supervised), Card 24, steps 1-3
**Issue:** Step 2's sleep only covers the "lock not acquired" case; a loser whose step-1 dial fails against a state the winner already wrote (mid-bind, since the winner releases the lock before its own dial-retry loop) can acquire the now-free lock, see the state healthy in step 3, release, and loop back to step 1 immediately — a tight spin for the duration of the daemon's bind window.
**Fix:** Add a short sleep (e.g. 50ms) on the step-3 "healthy, loop back" path too, not just step 2's "lock not acquired" path.
