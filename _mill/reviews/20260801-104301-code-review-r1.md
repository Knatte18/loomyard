## Findings

### [BLOCKING] Six engine config_test.go files assert a stale "lyx init" substring
**Location:** `internal/boardengine/config_test.go:194`, `internal/shuttleengine/config_test.go:121`, `internal/reedengine/config_test.go:131`, `internal/perchengine/config_test.go:203`, `internal/builderengine/config_test.go:141`, `internal/websterengine/config_test.go:172`
**Issue:** Card 27 (batch 6) retargeted all eight `config.go` "not initialized here" error messages from `run "lyx init"` to `run "lyx fabric reconcile"`. The plan claimed "the other six engines have no test asserting this exact string" — that claim is false: each of these six `TestLoadConfig_NotInitialized` tests still runs `strings.Contains(errMsg, "lyx init")`, which now evaluates false against the new message (`"lyx fabric reconcile"` does not contain `"lyx init"`). This is a real, reproducible test failure in six packages.
**Fix:** Update each of these six assertions to check for `"lyx fabric reconcile"` instead of `"lyx init"`, mirroring the fix already correctly applied to `internal/loomengine/config_test.go:113` and `internal/fabricengine/config_test.go:138-139`. None of batch 6's or any other batch's `verify:` command covers these six packages, so this escaped every batch gate; only `go test ./...` (the done_gate) would catch it.

### [NIT] Stale reference to deleted `initengine/init.go` in a WireJunctions doc comment
**Location:** `internal/fabricengine/junction.go:36`
**Issue:** The doc comment for `WireJunctions` still names `initengine/init.go` as one of three callers ("initengine/init.go, fabricengine/checkout.go, and fabricengine/reconcile.go all call WireJunctions"). `internal/initengine` is deleted in this same batch (card 25); card 28's sweep covers `junctionnames.go`/`weftgit.go`/`reconcile.go` comments and `junction.go`'s user-facing error text (line 152, correctly updated) but missed this doc-comment reference to the now-nonexistent package/function.
**Fix:** Reword the comment to name the current WireJunctions callers only (`checkout.go`, `reconcile.go`, `add.go`, and the fabriccli clone handler), dropping the `initengine/init.go` mention.

### [NIT] configreg.go package doc still mentions "init" CLI commands
**Location:** `internal/configreg/configreg.go:4`
**Issue:** "Provides a neutral registry of available config modules (board, fabric) and their templates, used by init and config CLI commands." — `init` is gone; this is a dangling reference to a deleted command, the exact class of miss card 28's sweep targets, but `configreg.go` was not in that card's file list.
**Fix:** Drop "init and" from the sentence (or reword to "used by the config CLI command and callers such as fabric clone").

### [NIT] `runUnwire` silently discards the `Getwd()` error, unlike every sibling handler
**Location:** `internal/fabriccli/unwire.go:23`
**Issue:** `cwd, _ := hubgeometry.Getwd()` discards the error, whereas every other fabric CLI handler (`runAdd`, `runList`, `runCheckout`, `runReconcile`, etc.) checks it and returns `output.Err`. This exact line was specified verbatim in the plan (card 24), so it's a plan artifact rather than an implementer deviation, but it is inconsistent with the codebase convention visible in every other handler in the same file/package.
**Fix:** Check the error and return `output.Err(out, err.Error())` on failure, matching every other verb in `fabriccli`.

## Verdict

REQUEST_CHANGES
Six engine config_test.go files assert a now-false "lyx init" substring after card 27's message retarget — real cross-package test failures.
