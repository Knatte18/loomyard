## Findings

### [BLOCKING] githubclient's whole functional test suite is Windows-only, contradicting the plan's explicit no-build-tag requirement
**Location:** `internal/githubclient/githubclient_test.go:1` (`//go:build windows`)
**Issue:** The entire file — `TestResolveToken_Chain`, `TestCache_ConcurrentWriters`, both `TestAuthRT_*` 401-replay/body-rewind cases, the timeout case, etc. — is gated behind `//go:build windows`, so on any non-Windows machine (including this Linux review environment) `go test -race -count=1 ./internal/githubclient/...` compiles and runs zero of these cases; only the untagged `leaf_enforcement_test.go` executes. Batch 6's own "Batch Tests" section (`_mill/plan/06-githubclient.md`) states unambiguously: "These tests are untagged Tier 1 ... so they must **not** carry a build tag." Only the DACL assertion (`assertOwnerOnlyDACL`, which uses `golang.org/x/sys/windows`) is genuinely Windows-specific; the resolution-chain, cache-TTL, concurrent-writer, and 401-replay/body-rewind cases are platform-agnostic and were required by card 30 to run on any machine with no `gh` and no credentials. The repo already has an established convention for exactly this split — `internal/githubclient/cache.go` / `cache_windows.go` / `cache_other.go` (mirroring `internal/fslink`'s three-file split) — that was simply not applied to the test file.
**Fix:** Split into an untagged `githubclient_test.go` (every case not touching `golang.org/x/sys/windows`) plus a `//go:build windows`-tagged file carrying only `TestWriteCachedToken_CreatesFileWithRestrictivePermissions`/`assertOwnerOnlyDACL`, sharing the `setCacheDir`/`seedCacheFile`/`withFakeGHAuthToken`/server helpers via the untagged file.

### [NIT] Batch 1's linked-worktree+junction fixture (card 3) is dead code — never called anywhere
**Location:** `internal/gitrepo/fixtures_test.go:48-163` (`linkedWorktreeFixture`, `newLinkedWorktreeFixture`, `newLinkedWorktreeFixtureViaJunction`)
**Issue:** These are annotated `//nolint:unused // first exercised by batch 2's parity/oracle test files`, but no test in the repo ever calls them — `internal/gitrepo/parity_test.go` (same package, `gitrepo_test`) never references `linkedWorktreeFixture`; instead `internal/gitrepo/gogit_test.go` (package `gitrepo`, a different Go package that legitimately can't reach these) built its own separate `gogitLinkedFixture`/`linkedParityFixture` types and duplicated `oracleCurrentSHA`/`oracleSHAExists`/etc. a second time to cover both exported- and unexported-method linked-worktree parity together. The stale doc comment ("Not yet used within this batch") is now simply false — there is no future caller left in the plan.
**Fix:** Either wire the exported-method linked-worktree parity checks in `parity_test.go` through this fixture (freeing `gogit_test.go`'s duplicate to cover only the unexported methods), or delete the three unused symbols from `fixtures_test.go` as dead weight from a batch-1 deliverable batch 2 chose not to consume.
