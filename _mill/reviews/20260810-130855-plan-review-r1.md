## Findings

### [NIT:consistency] `branchRequest` gains an undeclared `branchPrefix` field
**Demoted-from:** BLOCKING
**Location:** Overview `## Shared Decisions` "exact Go type shapes for the gate" vs. batch 2 card 6, batch 5 cards 23/24/25/26
**Issue:** The Shared Decision pins `branchRequest{what, repoDir, branch, ownership, dirtiness, force}` explicitly "so no batch invents its own," but card 6 requires adding "an additional `branchPrefix string` field set by each call site from its own `t.cfg.BranchPrefix`," and cards 23, 24, 25, 26 all construct `branchRequest` literals naming a `branchPrefix` field that the pinned shape does not have. This also contradicts the discussion's own "each check's inputs travel with the check, not on the request" rule (the same rule that rejected hoisting `l` onto the request) — `branchPrefix` is an input `ownedManagedBranch`'s predicate needs, so by that rule it belongs on the ownership-kind constructor (`ownedManagedBranch(l, branchPrefix)`), not as a bare request field nobody pinned.
**Fix:** Amend the Shared Decision's pinned `branchRequest` shape to include `branchPrefix`, or move it onto `ownedManagedBranch`'s constructor signature to match the per-kind-inputs principle; either way, state it once so cards 6/23/24/25/26 agree with the pinned type and each other.

### [BLOCKING:design] `createGitWorktree`'s literal return signature mis-declares its first value
**Location:** Batch 2, card 9
**Issue:** The card specifies `createGitWorktree(repoDir string, addArgs []string, target string) (createdToken, exitCode int, stderr string, err error)`. In Go, `createdToken, exitCode int` is a name-group: both `createdToken` and `exitCode` become named return values of type `int`, shadowing the package-level `createdToken` type inside the function body. As written, the function cannot return the intended `createdToken` struct at all — `createdToken{path: ..., worktree: true}` fails to compile inside its own shadowed scope, contradicting the very next sentence's instruction to "return a token with `path` set to ...". Card 9's sibling minter, `createExclusiveDir(path string) (createdToken, error)`, does not have this problem since it has no following identifier to group with.
**Fix:** Spell the signature with an explicit name for the first return, e.g. `(tok createdToken, exitCode int, stderr string, err error)`, so the group-by-type parse does not consume `createdToken` as an `int`-typed identifier.

### [NIT:scope] Card 27 omits `_mill/discussion.md` and `doc.go` from Context despite relying on both
**Location:** Batch 6, card 27
**Issue:** Card 27's allowlist rationale text closely tracks the discussion's `bypass-guard-shape-and-home` section (the `RemoveAll(`/`warp.ResetHard(` corrections, the full allowlist-with-reasons) and asserts a fact about `doc.go` ("its only non-comment line is the package clause") without listing either file in Context — unlike every other card in this batch, which lists `_mill/discussion.md`.
