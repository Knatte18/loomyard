## Findings

### [BLOCKING] Card 9's self-heal assertion contradicts WeftSHAForWarpSHA
**Location:** Batch 3, Card 9 (same claim repeated in Card 7's `PartialCommitError` doc and the `partial-failure-report-three-outcomes` Shared Decision)
**Issue:** Card 9 asserts that after clearing the corrIndexPath block, a bare `f.WeftSHAForWarpSHA(result.WarpSHA)` "self-heals via RebuildIndex to result.WeftSHA" — but `index.go`'s (unedited) `WeftSHAForWarpSHA` only retries `RebuildIndex` on a *stale* hit (`ok==true`, `SHAExists` false); a directory-blocked `RecordCorrespondence` never wrote an entry at all, so the lookup hits `!ok` and returns `ErrNoCorrespondence` immediately, never reaching `RebuildIndex`.
**Fix:** Have the test explicitly call `f.RebuildIndex()` before the lookup (or scope a fix into `index.go`), and correct the same "self-heals via RebuildIndex" wording wherever it's repeated.

### [BLOCKING] Card 11 Context omits gitrepo's existing fixture helpers
**Location:** Batch 4, Card 11
**Issue:** Context lists only `gogit.go`/`gitrepo.go`, omitting `internal/gitrepo/gitrepo_test.go`, which already defines `newRepo`/`writeFile`/`commitAll` in package `gitrepo_test` — the natural home for the new `worktree_test.go`'s clean/modified/untracked/staged fixtures. Without it in Context, the implementer is likely to redeclare same-named helpers (a same-package compile collision) or duplicate fixture logic from scratch.
**Fix:** Add `internal/gitrepo/gitrepo_test.go` to Card 11's Context and instruct reuse of `newRepo`/`writeFile`/`commitAll`.

### [BLOCKING] classifyPaths comparison under-specifies Windows path-sep handling
**Location:** Batch 1, Card 1
**Issue:** The spec normalizes the input path via `filepath.ToSlash` before comparing against a junction prefix built from `ScopedPathspec`→`filepath.Join`, which emits OS-native separators; it never states the prefix itself is also normalized. On Windows with `relPath != "."`, a prefix like `sub\_lyx` would fail to match a ToSlash'd `sub/_lyx` input. Production use pins `relPath="."` this slice (masking it), but the pure function is unit-tested with `relPath="sub"` and is explicitly built for later multi-subpath slices.
**Fix:** State explicitly that both the input path and every computed junction prefix are `filepath.ToSlash`-normalized before comparison.

### [NIT] SkipGit's doc comment goes stale for Fabric.Commit
**Location:** Batch 3, Card 7 / Batch 5, Card 14
**Issue:** `fabric.go`'s `SyncOptions.SkipGit` comment says "Skip all git operations if true," but Card 7/10 only gate the weft side on it — the warp commit and the async push (env-var-gated only, helper-internal) proceed regardless, a deliberate but undocumented scope narrowing.
**Fix:** Have Card 14's `doc.go` pass (or a small `fabric.go` touch-up) state `SkipGit` is weft-scoped for `Fabric.Commit`.

### [NIT] Card 6 hand-builds a warp fixture CopyHostHub already provides
**Location:** Batch 2, Card 6
**Issue:** The card directs building the warp-side repo "via `lyxtest.MustRun` git commands" from scratch, but `lyxtest.CopyHostHub` is a cached template already shaped exactly as needed: a repo with an unpushed commit against an empty bare origin.
**Fix:** Reuse `lyxtest.CopyHostHub` for the warp side instead of hand-building it.

### [NIT] Card 5 leaves stale file-header doc comments
**Location:** Batch 2, Card 5
**Issue:** After this card, `fabriccli/spawn.go`'s `spawnPush` becomes a one-line delegator (the detach/process-group prose in its header no longer describes what the file does) and `weft_verbs.go`'s header still describes only one hidden flag; neither update is called out.
**Fix:** Update both files' header comments to reflect the delegation and the two-flag bypass.

### [NIT] Card 13's exclude-file assertion rests on an unverified go-git behavior
**Location:** Batch 4, Card 13
**Issue:** The `Fabric.Status` test assumes go-git's `Worktree.Status()` honors `.git/info/exclude` (not just tree `.gitignore` files) so `.weft/`/`.gitrepo-push.lock` are omitted; this external-library behavior isn't otherwise exercised or confirmed anywhere in the codebase.
**Fix:** Spike this assumption early; if unsupported, `WorktreeChangedFiles` needs its own exclude-file filtering.

### [NIT] Card 11's raw Lock() is a third, undocumented locking pattern
**Location:** Batch 4, Card 11
**Issue:** Holding `r.goGitMu.Lock()` directly around `wt.Status()` is sound but is neither of gogit.go's two documented categories (RLock for plain ref reads, `lookupObjectRetrying` for object lookups); `gogit.go`'s own locking-discipline doc isn't updated to acknowledge it.
**Fix:** Add a short addendum to `gogit.go`'s doc noting `Status()` as a write-locked, non-retried third category.
