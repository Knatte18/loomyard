## Fixed

- r6 holistic, `[BLOCKING:design]` "Reap log suppressed after a partial kill" — confirmed, and the most consequential finding of the review. `reconcileLocked` returns `killed, fmt.Errorf("kill pane %s: %w", ...)` from *inside* its kill loop, so a failure on a later pane returns with earlier panes already destroyed;
  both callers then discard the returned `killed` slice (`reconcileApplyPersistLocked`'s `return nil, fmt.Errorf("reconcile: %w", err)` and `Resume`'s identical site, verified in `spawn.go` and `lifecycle.go`), and card 6 adds a third of the same shape. Card 3's "success path only — an early return must not log" instruction would therefore have produced exactly the silent pane destruction that the-reap-logs-what-it-destroys exists to prevent, in the case where the operator most needs the trace. The card now requires the killed ids accumulated into two locals as the loops progress and the single `Info` line emitted from a `defer` firing whenever either is non-empty, so both paths are covered by one site that cannot drift;
  it states that the error still propagates unchanged and that a reconcile killing nothing still logs nothing on either path. A third assertion was added to card 3's test — an `execHook` that succeeds for the first pane and fails for the second must still produce a line naming the destroyed pane — because without it the `defer` could be deleted and the suite would stay green.
- r6 holistic, `[NIT:scope]` "Card 7's Context omits overlay.go" — confirmed: card 7 names `e.tmux.execHook`, declared in `internal/reedengine/overlay.go`, which card 3 lists for the same identifier but card 7 did not. Added, for parity. The gap was masked only because the listed `lifecycle_test.go` happens to demonstrate both the hook shape and the `list-panes` line format.
- r6 holistic, `[NIT:consistency]` "Card 14 preserves an already-false sole-pane premise" — confirmed against `strand.go`: `removeStrandLocked` collects pane ids from strands only, and the header is never a strand, so after removing the last strand the removed pane is not the session's last pane and `kill-pane` removes it outright rather than corpsing it under `remain-on-exit`. Card 14 had carried that corpse premise forward as justification for scoping its rewrite to "only the adoption framing". Note this premise was falsified by the header pane in an earlier round, not by this task — card 14 is simply the right owner, since it is already rewriting that test's prose and card 12 would otherwise find stale text with no card to attribute it to. The card now requires the doc comment and the skip string restated to what the scenario actually exercises, with an explicit instruction not to invent assertions to match, since the existing ones already cover it.
