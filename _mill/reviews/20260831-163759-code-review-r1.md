## Findings

### [BLOCKING:design] `--max-entries` with a leading-zero value hits bash octal parsing
**Location:** `plugins/prowler/scripts/github-tree.sh:105-107` (validation), `:255` (comparison)
**Issue:** The guard's validation (`case "$MAX_ENTRIES" in ''|*[!0-9]*) usage ;; esac`) accepts any all-digit string including ones with a leading zero, but `emit`'s `[ "${#output[@]}" -gt "$MAX_ENTRIES" ]` is a bash arithmetic comparison, and bash interprets a leading-zero numeric literal as octal. `--max-entries 018` (or any leading-zero value containing an 8 or 9) crashes with "value too great for base"; `--max-entries 010` silently applies a ceiling of 8, not 10 — a real, reachable correctness bug, not hypothetical, and untested by card 6's scenarios (none use a leading zero).
**Fix:** Either reject a leading-zero multi-digit value in the validation case pattern, or force base-10 at the comparison site, e.g. `$((10#$MAX_ENTRIES))`.

### [BLOCKING:consistency] New README prose leaves independent-clause boundaries unsplit, against the batch's own Shared Decision
**Location:** `plugins/prowler/README.md:36`, `:46-47`
**Issue:** The plan's "markdown edits follow semantic line breaks" Shared Decision binds batch 3 and explicitly covers newly-added lines, requiring a break at a comma-plus-coordinating-conjunction or semicolon boundary where what follows has its own subject and verb. Line 36 ("...tens of thousands of paths, and the abort is an ordinary...") and lines 46-47 ("...grows with file size, and the two are roughly..."; "...the skill already requires; `curl` is optional, and its absence costs speed...") each keep such a boundary on one physical line. This is inconsistent with the same file's own correctly-split neighbors added by the same card (e.g. `README.md:33-34`, `:37-38`), showing the convention was applied selectively rather than uniformly.
**Fix:** Break each cited line at its comma+conjunction / semicolon boundary onto its own line, matching the pattern already used elsewhere in the same file's new content.
