## Findings

### [BLOCKING] Card 17 migration leaves `weftBaseDir` a dead variable
**Location:** Batch 4 (clone-does-everything), Card 17, part (a)
**Issue:** `weft_verbs.go`'s `PersistentPreRunE` declares `weftBaseDir := filepath.Join(l.WeftWorktree(), l.RelPath)` (line 122) solely to feed `LoadConfig(weftBaseDir)` (line 124). Card 17 instructs switching that call's base to `hubgeometry.BoardDir(l.Hub)` but says nothing about the now-orphaned `weftBaseDir` declaration — it is used nowhere else in the closure, so Go will refuse to compile ("declared and not used").
**Fix:** Add an explicit instruction to remove the `weftBaseDir` declaration (and its preceding comment) when switching the `LoadConfig` base to `hubgeometry.BoardDir(l.Hub)`.

### [BLOCKING] `doc.go`'s stale `lyx init` mentions are never swept
**Location:** Batch 6 Card 28 / Batch 7 Card 32
**Issue:** `internal/fabricengine/doc.go` names `lyx init` as a live command/remedy four times (lines 34, 36, 38, 42 — e.g. "The remedy is one `lyx init` … or one `lyx fabric reconcile`"). Card 28's "sweep remaining `lyx init` reference strings and comments" exhaustively lists `reconcile.go`, `junction.go`, `junctionnames.go`, `weftgit.go`, `fabric.go`, `configsync.go` as Edits — `doc.go` is absent. Card 32 (batch 7, the only later card that edits `doc.go`) only *appends* a new paragraph block near the existing junction/pathspec paragraphs; its Requirements never ask to reword the pre-existing stale mentions. After batch 6, these four lines reference a deleted command as a still-valid remedy.
**Fix:** Add `internal/fabricengine/doc.go` to card 28's sweep (or extend card 32's Requirements) to reword all four `lyx init` mentions to `lyx fabric reconcile`/clone-does-everything wiring.

### [BLOCKING] Batch 3's own "Batch Tests" section contradicts its `verify:` field
**Location:** Batch 3 (configsync-fabric-repowide), "Batch Tests" section
**Issue:** The batch frontmatter and 00-overview.md's DAG both pin `verify: go test -tags integration ./internal/configsync/... ./internal/initengine/...` (needed because Card 11 adds `t.Skip(...)` to integration-tagged `initengine` tests, which only compile/run under `-tags integration`). The batch's own "Batch Tests" narrative instead describes `verify: go test ./internal/configsync/...`, explicitly stating "no `-tags` needed" and omitting `initengine` entirely — a self-contradiction that, if followed instead of the frontmatter, would never build the just-edited (skip-neutralized) `initengine` test files and could hide a compile break there until batch 6.
**Fix:** Rewrite the "Batch Tests" paragraph to match the real `verify:` command and explain why `internal/initengine` and `-tags integration` are included.

## Verdict

Two compile/doc-completeness gaps (dead variable, stale doc references) and one self-contradictory batch verify description.
