## Findings

### [BLOCKING:design] fetch()'s root/child kind not bound to call sites
**Location:** batch 2, card 5 (`fetch <endpoint> <kind>`)
**Issue:** `fetch`'s error branches key off `<kind>` being `root` vs `child` (plus path-emptiness), but the walk-processing paragraph (how `rec`/`nonrec` queue items are handled) never states which fetch call passes which `<kind>` value — it is only inferable, not specified, unlike every other identifier in this card.
**Fix:** state explicitly that `kind=root` applies only to the two calls addressing the walk's seed item (its `rec` fetch and its `nonrec` fallback, both using `BASE_REF`), and `kind=child` to every fetch issued while draining the rest of the queue.

### [BLOCKING:design] path-validation loop is locale-dependent for multi-byte characters
**Location:** batch 2, card 5 (path character-by-character walk); batch 1, card 4, test 17 (`naïve`)
**Issue:** the "walk it character by character" step used to name the first offending character assumes bash string indexing is codepoint-aware; under a `C`/POSIX locale (common in minimal/CI shells and never pinned anywhere in this plan) a multi-byte UTF-8 character like `ï` is sliced at the byte level, so the reported "character" can be a single invalid byte rather than `ï` — exactly the case test 17 exercises, risking a spurious failure or garbled diagnostic depending on the runtime locale.
**Fix:** either pin a UTF-8 locale (e.g. `export LC_ALL=C.UTF-8` near the top of `github-tree.sh`) and record the assumption in the header comment, or specify a byte-safe/regex-based extraction instead of character-indexed iteration, and state the chosen guarantee explicitly in Requirements.

### [NIT:consistency] harness assertion wording drifts from the fixed 403 stderr string
**Location:** batch 1, card 4, test 13 vs batch 2, card 5
**Issue:** card 5 fixes the 403 message as containing "rate limited"; card 4's test 13 describes the assertion as "mentions rate limiting" — a different word form that could tempt an implementer into grepping for a substring the fixed message doesn't literally contain.
**Fix:** reword test 13 to reference the literal fixed substring ("rate limited") rather than a paraphrase.

### [NIT:consistency] generic fallback error message can exceed the documented "one stderr line" contract
**Location:** batch 2, card 5 (`fetch`'s "anything else" branch; SKILL.md failure-contract paragraph)
**Issue:** the generic branch embeds the raw, unparsed `gh api` response body verbatim in the diagnostic; if that body ever spans multiple lines, the script prints more than the single stderr line the rewritten SKILL.md promises callers.
**Fix:** note this as an accepted edge case in the header comment (bodies are expected single-line), or soften the SKILL.md wording to allow a possible multi-line diagnostic on the unmatched-status path.

## Verdict

REQUEST_CHANGES
Two design gaps need closing: fetch()'s root/child call-site wiring, and locale-safe handling of the multi-byte path-character check.
