## Findings

### [BLOCKING] `go/token` import collides with local `token` var
**Location:** batch 1 / Card 4
**Issue:** Card 4's walk callback already has `token, bad := firstBannedToken(data)` (a `string`) declared earlier in the same closure; the same card then adds `"go/token"` to the imports and calls `token.NewFileSet()` in that same scope. The local `token` shadows the package identifier for the rest of the closure, so `token.NewFileSet()` will not compile (`token.NewFileSet undefined`, `token` being a string). This breaks `go build`/`go vet`/`go test` for `cmd/lyx`, failing batch 1's own `verify:` immediately.
**Fix:** Rename the banned-token local variable (e.g. `bannedTok, bad := firstBannedToken(data)`) or import `go/token` under an alias (e.g. `gotoken "go/token"`) and call `gotoken.NewFileSet()`.

### [NIT] `allowedLongSleepers` rationale misattributes safety to `refuseCLIReexec`
**Location:** batch 1 / Card 3
**Issue:** The prescribed map-value text claims both sleep loops are safe because `lyxtest.HermeticGitEnv`'s `refuseCLIReexec` "already refuses" the reed re-exec path. `internal/reedengine/testmain_test.go` never imports or calls `lyxtest` at all, and `internal/reedcli/testmain_test.go`'s own `if os.Args[1]=="reed"` branch (the sleep loop) unconditionally returns/blocks before ever reaching its later `lyxtest.HermeticGitEnv()` call — so `refuseCLIReexec` never actually fires on this exact path in either file. This inaccurate reasoning ships as a comment in `cmd/lyx/tiersleep_test.go`.
**Fix:** Reword the rationale to cite each file's own `TestMain` intercept (the header-pane-keepalive fix itself, which IS what makes the branch safe/intended) rather than `refuseCLIReexec`.

### [NIT] CONSTRAINTS.md bullet under-describes the guard's unresolvable-flag scope
**Location:** batch 1 / Card 5
**Issue:** Card 5's prescribed CONSTRAINTS.md text says the new guard flags "a literal `time.Sleep(...)` call whose duration argument is a compile-time constant ≥ 1 second," but Card 3 also makes any *unresolvable* Sleep-argument shape (not just a resolved constant) return `found = true` (the conservative-flag design, explicitly required by Card 3). The invariant's authoritative prose never mentions this broader trigger.
**Fix:** Add a clause to the new "Real-time-wait guard (additive)" bullet noting an unresolvable/non-constant argument shape is also conservatively flagged, forcing an allowlist entry or rename.

### [NIT] `sleepDurationAtLeastOneSecond`'s ParseFloat failure path unspecified
**Location:** batch 1 / Card 3
**Issue:** Case (b)'s spec says to compute `literal-value * scale` via `strconv.ParseFloat` on the literal's text, but never states the outcome when `ParseFloat` errors (e.g. a non-decimal literal). Left to implementer guesswork.
**Fix:** State explicitly that a `ParseFloat` error sets `unresolvable = true`, consistent with the conservative-flag default used for every other unrecognized shape.
