## Findings

### [NIT:consistency] mergestate.go's raw JSON I/O reintroduces a known torn-read race
**Demoted-from:** BLOCKING
**Location:** batch 2 / card 4 (`internal/fabricengine/mergestate.go`)
**Issue:** `saveMergeState`/`loadMergeState`/`deleteMergeState` are specified via raw `json.MarshalIndent`+`os.WriteFile(0o644)`, a raw read with `os.IsNotExist`, and raw `os.Remove` — unlocked. This is the same weft-gitdir location as the correspondence index (`index.go`/`corrindex.go`), which instead uses `internal/state`'s locked, atomic-replace `WriteJSON`/`ReadJSON`/`UpdateJSON` (verified: `corrindex.go` calls `state.ReadJSON`/`state.UpdateJSON` exclusively, never raw `os.WriteFile`). Raw `os.WriteFile` truncates then writes — a concurrent reader can observe a torn/empty file — which is exactly the hazard CONSTRAINTS.md's Fabric Git Invariant calls out for `.git/info/exclude` and mandates a locked read-modify-write for. Here, sibling-verb guard reads (`mergeBlocksMutation`, card 13's `Commit`/`Pull`/`Checkout`/`Remove` refusals) race unsynchronized against `saveMergeState`/`deleteMergeState` writes made while `MergeIn`/`Merge` hold the unrelated "combined write lock" — a torn read would hit `loadMergeState`'s "a corrupt file is an error, never silently adopted" clause and surface a spurious hard error instead of a clean guard result.
**Fix:** specify `mergestate.go`'s three helpers in terms of `internal/state.ReadJSON`/`WriteJSON` (with `path+".lock"`) rather than raw `os`/`json` calls, matching `index.go`'s own cited placement precedent; this also removes the need for `saveMergeState`'s entry in `uncontainedwrite_test.go`'s allowlist (raw `os.Remove` for `deleteMergeState` still needs its `destructiveguard_test.go` allowlist entry, since `internal/state` has no delete primitive — matching `index.go`'s own precedent there).

## Verdict

APPROVE
mergestate.go's raw, unlocked JSON I/O deviates from the codebase's own locked-state convention and reintroduces a documented torn-read hazard.
