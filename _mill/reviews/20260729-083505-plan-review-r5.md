## Findings

### [BLOCKING] Card 8's Edits: field omits toolchain.go despite mandating a production edit
**Location:** batch 02-toolchain-manager, Card 8
**Issue:** Card 8 lists `Edits: none` (only `Creates: toolchain_test.go`), but its own Requirements say "add a minimal package-level var seam... `var userCacheDir = os.UserCacheDir`... wire `goToolchainCacheDir`/`goToolchainInstallLock` to call `userCacheDir()`... but make the edit in `toolchain.go`, not by duplicating the helpers in the test file" — a real production-code change to a file the card's own metadata doesn't declare.
**Fix:** Add `internal/codeintelengine/toolchain.go` to Card 8's `Edits:` list.

### [BLOCKING] Card 24 constructs daemonState/uses its accessors with daemonstate.go missing from Context
**Location:** batch 06-ensure-server-supervised, Card 24
**Issue:** `ensureSupervised`'s Requirements directly call `readDaemonState`, `writeDaemonState`, `daemonStale`, construct a `daemonState{PID, Address, ProtocolVersion, StartedAt}` literal, and reference `supervisedProtocolVersion` — all defined in `internal/codeintelengine/daemonstate.go` (card 14) — but that file is absent from Card 24's `Context:` (which lists hubgeometry.go, lock.go, proc_windows.go, lspclient.go, errors.go only).
**Fix:** Add `internal/codeintelengine/daemonstate.go` to Card 24's `Context:`.

### [BLOCKING] Card 25's test directly drives internal/lock with lock.go missing from Context
**Location:** batch 06-ensure-server-supervised, Card 25
**Issue:** The retry-exhaustion sub-test in `supervised_test.go` must "pre-acquire the spawn lock in the test itself (hold it for the sub-test's duration)" — i.e. call `lock.TryAcquireWriteLock`/`Release` directly — but `internal/lock/lock.go` is not listed in Card 25's `Context:`.
**Fix:** Add `internal/lock/lock.go` to Card 25's `Context:`.

### [BLOCKING] Several cards construct errors.go/symbol.go types without listing those files in Context
**Location:** batch 08-definition-and-symbol-engine Card 30; batch 09-cli-definition-and-symbol Card 37; batch 10-batch-mode-cli Card 42
**Issue:** Card 30 constructs `&ErrResolverUnsupported{...}` and `&ErrSymbolNotFound{...}` with `internal/codeintelengine/errors.go` absent from Context (only refs.go/position.go listed). Card 37 constructs `&codeintelengine.ErrAmbiguousSymbol{...}` and `&codeintelengine.ErrSymbolNotFound{...}` with errors.go absent from Context. Card 42 builds `[]codeintelengine.SymbolMatch{...}` with `internal/codeintelengine/symbol.go` absent from Context. Field names happen to be spelled out in each card's prose, but per the Context-completeness rule this is still a gap.
**Fix:** Add `internal/codeintelengine/errors.go` to Cards 30 and 37's Context; add `internal/codeintelengine/symbol.go` to Card 42's Context.

### [NIT] Card 1 mentions ConfigTemplate() from an uncontexted file
**Location:** batch 01-registry-and-state-foundations, Card 1
**Issue:** The Requirements note "`ConfigTemplate()` in `template.go` needs no edit" — `template.go` isn't in Card 1's Context or Edits. Low-risk since it's explicitly telling the implementer not to touch it, but still an uncontexted file mention.
**Fix:** Either add `internal/codeintelengine/template.go` to Context, or drop the aside since it asserts a fact about a file the implementer never needs to open.

### [NIT] Card 21's shared-daemon regression assertion lacks a concrete pass condition
**Location:** batch 05-ensure-server-native, Card 21
**Issue:** The sub-test's acceptance criterion is "checking neither returns an unexpected empty result" — vague enough that two different implementers could write non-equivalent, non-deterministic assertions.
**Fix:** Name a concrete query/expected result (e.g. issue `workspace/symbol` for a known package-level symbol on both connections and assert both return ≥1, identical candidate).
