## Findings

### [BLOCKING] Card 11's new escalation path leaves lock-release unspecified and untested
**Location:** batch 4, card 11 (`ensureSupervised` wedged-daemon escalation)
**Issue:** The escalation acquires the spawn lock, then calls `reconnectUnderLock` while holding it, but the Requirements never say to `fileLock.Release()` before returning on the two new terminal outcomes — the reuse-success return (`healthy==true`, "do not kill") and the deadline-guard timeout return. Every existing return-while-holding-the-lock path in `ensureserver.go` (steps 2, 3, 4-7) explicitly releases first; a `gofrs/flock` handle left unreleased stays held for the rest of the process, so a batch-mode CLI call (which invokes `ensureSupervised` once per positional arg in the same process) would silently wedge every subsequent lookup behind a lock nobody ever frees.
**Fix:** State explicitly that both new return paths (reuse-success and deadline-timeout) must `fileLock.Release()` before returning, mirroring steps 2/3's existing pattern; add a `supervised_test.go` case that drives the escalation through to a successful `reconnectUnderLock` reuse (not just the always-fails-dial timeout case already covered) and asserts a subsequent call in the same process can still acquire the lock.

### [BLOCKING] Card 12 references `TestEnsureNative_Integration` from a file absent from its Context/Edits
**Location:** batch 4, card 12 (`ensureServer` flip)
**Issue:** Requirements justifies not threading `binPath` into `ensureNative` by naming its call site `TestEnsureNative_Integration`, which is defined in `ensureserver_integration_test.go` — that file is listed in neither card 12's `Context:` nor `Edits:` (`registry.go`, `toolchain.go` only). Per the Context completeness rule this is a cold-start-exploration gap: the implementer can't verify the claim without reading a file the plan never hands them.
**Fix:** Add `internal/codeintelengine/ensureserver_integration_test.go` to card 12's `Context:` list.

### [NIT] Shared Decision misattributes the `supervised_integration_test.go` doc fix to batch 4
**Location:** `00-overview.md`, "docs land in the same commit" Shared Decision
**Issue:** The Decision text lists the `supervised_integration_test.go` "no live path to it in V1" header-comment fix as landing in "batch 4," and its own "Applies to" line names only batches 2/3/4 — but the actual edit is batch 5's card 13 (confirmed against `04-engine-supervised-flip.md`'s cards, none of which touch that file). The card-level instructions are correct; only the overview's summary attribution is wrong.
**Fix:** Correct the parenthetical to "(batch 5)" and add batch 5 to the Decision's "Applies to" line.
