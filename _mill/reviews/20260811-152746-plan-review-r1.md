## Findings

### [NIT:consistency] Batch Index verify drops every tagged run
**Demoted-from:** BLOCKING
**Location:** `00-overview.md` batches 4/5/6 vs `04/05/06-*.md`
**Issue:** The authoritative `batches:` block gives batch 4 `go test ./internal/fabricengine/ ./internal/fabriccli/`, batch 5 the same, batch 6 `go test ./internal/fabriccli/ ./internal/output/` — each batch file adds a tagged half the index omits (`go vet -tags integration ...`, `go test -tags integration -run TestMutationRecord ...`, `go test -tags integration ./internal/fabriccli/`). Card 21's new `mutation_record_integration_test.go` and card 26's `cli_test.go` additions would therefore never be compiled or run by their own batch.
**Fix:** Make the `batches:` entries byte-identical to each batch file's `verify:`.

### [BLOCKING:scope] Signature changes break callers the plan never inventories
**Location:** batch 4 cards 12/14
**Issue:** Card 14 gives `WireJunctions` a leading `rec *Mutations`; its callers also include `internal/loomengine/preflight_integration_test.go:39`, `internal/configcli/configcli_integration_test.go:68`, `internal/fabricengine/healthreason_integration_test.go` (6 sites) and `internal/fabricengine/junction_repoint_test.go` (4 sites). Card 12 gives `(*Fabric).ResetHard` a leading `rec` and claims "its three callers in `internal/fabricengine/pull.go`" — `internal/fabricengine/warpforward_integration_test.go:134,171` also call it. None of these files appear in any `Edits:` or in `## All Files Touched`, and the loomengine/configcli two are outside every batch's verify scope (`go vet -tags integration ./internal/fabricengine/...` does not reach them), so the break survives to the done gate.
**Fix:** Add those files to the owning cards' `Edits:` and to `## All Files Touched`, and widen batch 4's vet to `./...`.

### [BLOCKING:design] `branch_pushed` has no branch name at two of its three sites
**Location:** batch 5 card 19
**Issue:** The card requires `rec.AppendRef(KindBranchPushed, <branch>, "")` in `(*Fabric).PushWeft` (`return f.weft.PushCoalesced()`), `PushWarpAt` (`return gitrepo.New(warpPath).PushCoalesced()`) and `CoalescePushBothAt` (`pushRebaseFreeLogged(path)`) — no branch name is in scope at any of them, and the card forbids "inventing a new derivation". Worse, `pushRebaseFreeLogged` converts `gitrepo.ErrPushRejected` into `nil`, so "record on success" would append a `branch_pushed` for a push that was rejected, breaking the record-only-on-observed-effect Shared Decision.
**Fix:** Name the exact resolution (e.g. `gitrepo.CurrentBranch` on each path) and the exact success predicate that excludes the swallowed-rejection path, or scope `branch_pushed` to the sites that already hold a branch (`pushWeftBranch`, add.go).

### [NIT:consistency] `Len()` cannot be both value-receiver and nil-safe
**Demoted-from:** BLOCKING
**Location:** batch 1 card 1 vs batch 3 card 7
**Issue:** Card 1 declares `func (m Mutations) Len() int` (value receiver); card 7 requires `Snapshot()` and `Len()` to be "safe on a nil `*Mutations` receiver" and adds a test for it. A value-receiver method dereferences a nil pointer and panics.
**Fix:** Declare `Len()` on `*Mutations` in card 1, and state the consequence for `res.Mutated().Len()` (non-addressable) at the `errWithRecord` call site.

### [NIT:consistency] Card 21's package and its fixture source disagree
**Demoted-from:** BLOCKING
**Location:** batch 5 card 21
**Issue:** The card says create `mutation_record_integration_test.go` "in `package fabricengine`" while "following the fixture conventions of `internal/fabricengine/remove_guard_integration_test.go`" — that file is `package fabricengine_test` and its fixture builder `newFabricFixture` is declared in the external test package, unreachable from the internal one.
**Fix:** Name `package fabricengine_test` (everything the card asserts — `RefusalOf`, `Mutated()`, `Remove`, `Add` — is exported), or name a fixture reachable from the internal package.

### [BLOCKING:scope] Card 32 must table twelve result types it cannot read
**Location:** batch 8 card 32
**Issue:** The card requires declaring "the twelve result-type names … with the file each is declared in", but `Context:`/`Edits:` list only `destroy.go`, `mutation.go`, `add.go`, `status.go`, `diff.go`. `RemoveResult`, `CheckoutResult`, `PruneResult`, `CleanupResult`, `UnwireVerbResult`, `UnwireResult`, `ReconcileResult`, `CommitResult`, `PullResult`, `CloneResult` and `PushResult` live in eleven files the implementer may not read.
**Fix:** Add `remove.go`, `checkout.go`, `prune.go`, `cleanup.go`, `unwire.go`, `junction.go`, `reconcile.go`, `commit.go`, `pull.go`, `clone.go`, `weftgit.go` to card 32's `Context:`.

### [NIT:consistency] The "fixed key set" invariant is false as planned
**Demoted-from:** BLOCKING
**Location:** Shared Decision `ok is unchanged…`, card 22, card 23, card 33
**Issue:** The Shared Decision, card 22's doc-comment text and card 33's CONSTRAINTS.md wording all assert `mutations`/`partial` are present "on every mutating verb, success and failure alike"; card 23 deliberately leaves the pre-verb-call `output.Err` sites (cwd/location resolution, `LoadConfig`, `usage: …`) emitting neither key. Card 33 would therefore write a machine-quotable invariant into `CONSTRAINTS.md` that the shipped envelope violates, and card 26's "failure path, empty record" assertion is ambiguous about which failure it means.
**Fix:** Carve the pre-flight failure class out explicitly in the Shared Decision, in card 22's doc text and in card 33's invariant wording ("every envelope emitted from a verb outcome").

### [NIT:consistency] `repo_advanced` contradicts the plan's own vocabulary decision
**Location:** batch 1 card 1, batch 5 card 20
**Issue:** The Shared Decision "Fabric Vocabulary Invariant applies to every new identifier and string" says `Kind` values use fabric/warp/weft vocabulary only; `KindRepoAdvanced` / `"repo_advanced"` uses "repo", which `CONSTRAINTS.md` calls "too vague to denote warp". Card 20 applies it to `f.warpPath` as well as `f.weftPath`.
