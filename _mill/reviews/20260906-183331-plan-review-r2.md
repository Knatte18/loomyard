## Findings

### [NIT:consistency] SetDurableSinkDir's "exact ... body" decision contradicts Card 4
**Demoted-from:** BLOCKING
**Location:** `## Shared Decisions` / `hub-mode-is-byte-identical` vs Batch 2, Card 4.
**Issue:** The Decision states `SetDurableSinkDir` "keeps its exact name, signature, and body," but Card 4's own Requirements extract everything after `sinkMu.Lock()` into a new unexported `resetDurableSinkLocked`, making `SetDurableSinkDir` "a lock-plus-delegate wrapper around it" — verified against the current body in `internal/logger/sink.go`'s `SetDurableSinkDir`, which Card 4 explicitly rewrites. The plan's own decision text and its own card requirement literally disagree.
**Fix:** Reword the Decision to preserve observable behavior/call-site contract (name, signature, reset semantics), not literal body text, or drop "body" from the enumerated list.

### [NIT:consistency] New wireHub-sink-sentinel test's cleanup falls outside Cards 5/6's stated scope
**Demoted-from:** BLOCKING
**Location:** Batch 3, Card 5 (webstercli) and Card 6 (burlercli), each card's third new wiring test.
**Issue:** Both cards add a new test proving `wireHub` leaves the durable sink untouched by calling `logger.SetDurableSinkDir(sentinelDir)` directly before invoking `wireHub`. Both cards then state the cleanup obligation as "every test in this file that reaches wireStandalone ... must register t.Cleanup(...)" — but this new test reaches `wireHub`, not `wireStandalone`, so it falls outside that literal instruction even though it directly calls the process-global setter. This contradicts the overview's own `sink-override-is-process-global` Decision, which requires cleanup for a test causing `SetDurableSinkDir` to be called "directly, or indirectly by driving a wireStandalone" — direct calls are explicitly in scope there. Skipping cleanup on this one test leaks a live override into every later test in the same binary, defeating the `testing.Testing()` suppression package-wide.
**Fix:** Add an explicit `t.Cleanup(func(){ logger.SetDurableSinkDir("") })` instruction for the wireHub-sentinel test itself in both Card 5 and Card 6, not only for tests that reach `wireStandalone`.

### [NIT:consistency] Card 5 and Card 6 specify cleanup coverage at different granularity
**Location:** Batch 3, Card 5 vs Card 6.
**Issue:** Card 6 explicitly names the four shipped burlercli tests that need the new `t.Cleanup` call (`TestWireStandalone_NeverReadsLoc`, `TestWire_ModeStandaloneSelectsStandaloneMode`, `TestWire_StandalonePinnedValues`, `TestWire_StencilsDirFlag`); Card 5 leaves the equivalent webstercli enumeration implicit ("every test in this file that reaches wireStandalone"), an avoidable asymmetry between two otherwise-parallel cards covering the identical fix.
**Fix:** Enumerate the shipped webstercli tests in Card 5 the same way Card 6 does (e.g. `TestWire_ModeStandaloneSelectsStandaloneMode`, `TestWire_PlanDirResolution`'s standalone subtests, `TestWire_StandaloneRootsResolveToTarget`, `TestWire_MatcherNeverNilOpenerNilOnlyInStandalone`'s standalone subtest), for symmetry.
