## Findings

### [BLOCKING] Four per-pair `fabric.yaml`-base call sites never migrated to the repo-wide base
**Location:** Batch 2 (`02-reconcile-declarative-convergence.md`), card 7 — consequences land in batches 3, 4, 6.
**Issue:** Card 7 migrates only `checkJunctionHealth` (reconcile.go:341) and `Reconcile`'s inline call (reconcile.go:161) to `RepoWiredNames`/`BoardDir`. Four other call sites still load the junction name-set via `junctionNames(filepath.Join(<pair's own weft base>, RelPath))`, unmigrated by any card in the plan: `reconcile.go:390` (`junctionRepointedDetail`), `drift.go:92` (`PairInSync`, wired into `internal/loomengine` preflight per its own doc comment), `checkout.go:156` (`Topology.Checkout`, hard error + rollback on load failure), and `remove.go:104` (`Topology.Remove`, best-effort no-op on load failure). Once batch 3 stops materializing a per-worktree `fabric.yaml` and batch 4's clone only ever writes it to `<BoardDir>/_lyx/config/fabric.yaml`, `configengine.Load` on the pair's own weft base returns "config file … not found" (the `_lyx/` dir itself still exists, populated by other modules, so `FindBaseDir` passes but the file read fails) for every worktree, forever. Concretely: `lyx fabric checkout` always hard-fails and rolls back (checkout.go:157-160); `PairInSync` always reports "junction check unavailable", which — per drift.go's own doc comment — permanently blocks loom's preflight seed check across every worktree; `lyx fabric remove` silently stops removing nested junctions; and a successful `Reconcile` repoint reports a misleading "cannot load fabric.yaml" Detail instead of the junction list. Pre-existing tests for these four sites likely stay green because they seed fabric.yaml directly via `lyxtest.SeedConfig` at the pair's own base rather than going through the new clone/`ReconcileAll` flow — the same masked-regression class card 19 already fixes for `cli_test.go`/`weft_verbs.go`, but missed here.
**Fix:** In card 7 (or a new card in batch 2), migrate all four sites to `RepoWiredNames(hostLayout)` / `RepoWiredNames(l)`, matching the treatment already given to `checkJunctionHealth`/`Reconcile`; add regression coverage that exercises `checkout`/`remove`/`PairInSync` against a hub produced by the new clone flow (no per-worktree fabric.yaml), not a `SeedConfig`-seeded fixture.

### [NIT] Card 15 self-qualifies calls with the enclosing package's own name
**Location:** Batch 4 (`04-clone-does-everything.md`), card 15.
**Issue:** The requirement text writes `fabricengine.CommitWeftAt(...)`, `fabricengine.PushWeftAt(...)`, and `fabricengine.SyncOptions{}` inside `CloneHub`, but `clone.go` is itself `package fabricengine` — a literal package-qualified self-reference doesn't compile. Card 23's parallel `Unwire` requirement correctly uses the unqualified forms (`EnvSyncOptions()`, `New(...)`, `PushWeftAt(...)`).
**Fix:** Drop the `fabricengine.` prefix in card 15's three call examples for consistency with card 23 and to avoid an implementer copy-pasting invalid Go.

Batch 2's per-pair-base migration is incomplete: checkout, remove, PairInSync/loom-preflight, and junctionRepointedDetail are left reading a base batches 3-4 remove.
