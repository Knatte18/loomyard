## Findings

### [BLOCKING] Batch 3 reuses batch 2 symbols but depends only on [1]
**Location:** 03-write-surface, Card 10 (and 00-overview batch index)
**Issue:** Card 10's `SetSnapshotSHA` in `write.go` is required to "reuse the local validators from batch 2 / card 6" (`validSnapshotKey`/`ErrInvalidSnapshotKey`) and `isStrictDescendant` "from card 7" — all defined in `read.go`, which batch 2 creates; but batch 3 declares `depends-on: [1]` and the scope claims it runs in parallel with batch 2. Built alone, `write.go` references undefined symbols and `go test -tags integration ./internal/gitnativepoc/` (the batch verify) fails to compile.
**Fix:** Change batch 3 `depends-on` to `[1, 2]` in both `00-overview.md` and `03-write-surface.md` (drop the parallel-with-batch-2 claim), or move Card 10 into batch 2. Duplicating the helpers in `write.go` is not viable: batch 4 merges `read.go`+`write.go` into one package and duplicate `isStrictDescendant`/validators cause a redeclaration error.

### [NIT] Batch 3 scope's "shares no files → parallel" reasoning is unsound
**Location:** 03-write-surface, Batch Scope
**Issue:** Parallel-safety is argued from file-disjointness, but Card 10 creates a symbol-level (same-package) dependency on batch 2's `read.go`, which file-disjointness does not capture.
**Fix:** After correcting the dependency, reword the scope so independence is claimed only for the truly-independent cards (8, 9), not 10.

## Verdict

REQUEST_CHANGES
Card 10 needs batch-2 symbols; batch 3's `depends-on: [1]` breaks its own compile/verify.
