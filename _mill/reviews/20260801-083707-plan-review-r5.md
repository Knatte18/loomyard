## Findings

### [BLOCKING] Pre-existing fabricengine fixtures never migrated to repo-wide BoardDir config
**Location:** batch 2 (card 7/10) and batch 5 (card 20/22), package `internal/fabricengine`
**Issue:** `newFabricFixture` (`reconcile_stale_registration_test.go`) and the ad hoc `lyxtest.CopyPairedLocal`+`lyxtest.SeedConfig(t, fixture.WeftPrime, …)` pattern used across `junction_pattern_integration_test.go`, `remove_junctions_integration_test.go`, and `add_rollback_adopt_test.go` seed fabric config only at the per-pair weft base — never at `hubgeometry.BoardDir(fixture.Hub)`. `CopyPaired`/`CopyPairedLocal` never materialize a `_board` dir at all (confirmed in `internal/lyxtest/lyxtest.go`, and independently acknowledged by card 19's own note for `fabriccli`'s fixtures). Once card 7 migrates `checkJunctionHealth`/`PairInSync`/`Reconcile`'s inline load to `RepoWiredNames(hostLayout)` = `WiredNames(BoardDir(l.Hub))`, tests like `TestPairInSync_RealDirNotAJunction`, `TestReconcile_RepairsPatternOnlyDrift`, and `TestStatus_ReportsPatternJunctionUnhealthy` get "host junction check unavailable: cannot load fabric.yaml" instead of their asserted junction-specific reasons — failing already at batch 2. Once card 20 (batch 5) folds `WiredNames(hubgeometry.BoardDir(l.Hub))` into `Topology.Add` unconditionally (hard-failing via `rollbackAdd` on load error), *every* `topology.Add(...)` call in every file using these unfixed fixtures that expects success (`TestReconcile_RecreatesHandDeletedWeftWorktree`, both `TestPrune_*` tests, `TestCleanup_DetachedHostHeadProtectsCheckedOutWeftBranch`, `TestRemove_TearsDownNestedJunction`, `TestReconcile_RepairsPatternOnlyDrift`, `TestStatus_ReportsPatternJunctionUnhealthy`, and card 22's own new "successful Add wires eagerly" assertion) breaks, because `WiredNames(BoardDir)` finds no `_board/_lyx/config/fabric.yaml`. This directly breaks batch 2's, batch 5's, and batch 6's own stated `verify: go test -tags integration ./internal/fabricengine/...` gates — this is exactly the "masked-regression pattern from the round-1/round-3 reviews" card 19 explicitly fixes for `fabriccli`, but the identical pattern is left unfixed inside `fabricengine`'s own test suite.
**Fix:** Add a card (or extend card 7/10) migrating `newFabricFixture` and the other ad hoc `CopyPairedLocal`+`SeedConfig(fixture.WeftPrime, …)` call sites to also seed `hubgeometry.BoardDir(fixture.Hub)/_lyx/config/fabric.yaml`, mirroring card 19's fabriccli fix.

### [BLOCKING] Batch 3 breaks the not-yet-deleted initengine test suite with no verify coverage until batch 6
**Location:** batch 3 card 11 (`internal/configsync/configsync.go`), vs. `internal/initengine/init_test.go`
**Issue:** Card 11 makes `ReconcileAll` skip fabric entirely, so a worktree no longer gets a per-worktree `fabric.yaml`, and `result.Modules` shrinks from `len(configreg.Modules())` to one fewer entry. `internal/initengine/init_test.go` (not deleted until batch 6 card 25) asserts a per-worktree `fabric.yaml` exists, `len(result.Modules) == len(configreg.Modules())`, and `fabricengine.LoadConfig(f.Layout.WorktreeRoot)` succeeds — all three break as soon as batch 3 lands. Batch 3's own `verify: go test ./internal/configsync/...` does not cover `internal/initengine`, and no other batch's `verify:` targets that package before batch 6 deletes it outright; several "Batch Tests" sections describe the repo-wide `go test ./...` as a per-batch backstop, so this genuinely broken intermediate state (batches 3 through 5, and the start of batch 6 before card 25 lands) has no verify command that catches it.
**Fix:** Either sequence card 25's `initengine` deletion to land in the same batch as (or immediately after) card 11's `ReconcileAll` change, or add a throwaway edit to `init_test.go` in batch 3 relaxing the fabric-specific assertions until batch 6 deletes the file outright.
