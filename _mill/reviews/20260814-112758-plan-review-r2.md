## Findings

### [BLOCKING:design] Root pre-run seeding forces a git spawn on every lyx invocation
**Location:** batch 3 (seeding-trigger), card 14 **Issue:** `seedStencils(cmd.Context())` is placed unconditionally in `newRoot()`'s `PersistentPreRunE`; `lyxcwd.Resolve` unconditionally spawns `gitexec.Run(["rev-parse","--show-toplevel"], cwd)` (`lyxcwd.go`'s `resolveCore`/`gitWorktreeRoot`) before any gate check, and cobra runs `PersistentPreRunE` for every Runnable command (any parent group has `RunE: clihelp.GroupRunE`, confirmed in `idecli/cli.go:29`) — only bare `--help` short-circuits before it. Unlike the adjacent trace-arming block it sits beside (guarded by `if !testing.Testing()`), the card gives `seedStencils` no such guard. Every plain command (`lyx config get`, `lyx board`, etc.) now pays a real subprocess spawn even when nothing needs stencils, and dozens of existing untagged `cmd/lyx` tests that call `run()` against a Runnable command (e.g. `exitcode_test.go`'s "lyx board (no subcommand)" case) newly spawn git as a side effect. **Fix:** Gate `seedStencils` behind `!testing.Testing()` like the adjacent block, or otherwise scope it so it does not fire for every command/test regardless of need.

### [BLOCKING:scope] template_test.go's RenderIntegrationPrompt call sites are left stale
**Location:** batch 6 (webster-runtime-read), card 26/28 **Issue:** Card 26 changes `RenderIntegrationPrompt`'s signature (adds a trailing `stencilsDir string` param). Card 27 updates the one production call site (`runlevel.go:469`), but no card updates `template_test.go`'s two calls (`websterengine.RenderIntegrationPrompt(plan, "/reports/integration.yaml", "/worktree")` at lines 662 and 677) — card 28's requirements only list the five raw accessors (`MasterTemplate`/`IntegrationTemplate`/`ImplementerBodyTemplate`/`ForkTemplate`/`RecoveryTemplate`), not the `Render*Prompt` wrappers. This leaves batch 6's own `verify: ... go test ./internal/websterengine/...` failing to compile. **Fix:** Add the two `RenderIntegrationPrompt` test call sites to card 28's requirements, threading a seeded `stencilsDir`.

### [NIT:consistency] Batch 9's restated verify omits its own go vet clause
**Location:** batch 9 (reed-rename-and-docs), "Batch Tests" section **Issue:** The batch's YAML frontmatter and `00-overview.md`'s Batch Index both state `verify: go build ./... && go test ./internal/reedengine/... ./internal/lyxcwd/... ./cmd/lyx/... && go vet -tags integration ./internal/websterengine/...`, but the prose "Batch Tests" section at the bottom of `09-reed-rename-and-docs.md` restates it without the `go vet -tags integration ./internal/websterengine/...` clause and never explains why that clause exists (card 40 edits `integration.go`/`integration_test.go`, both presumably `//go:build integration`). **Fix:** Restate the full verify string in "Batch Tests" and note it exists to catch a compile break in the integration-tagged websterengine files card 40 touches.

### [NIT:scope] Several stated test call-site counts are inaccurate
**Location:** batch 4 card 18, batch 5 card 24 **Issue:** Card 18 claims "32 `composePrompt(...)` call sites" in `internal/burlerengine/prompt_test.go` (actual: 12) and "7 `New(shuttle, ...)` call sites" in `engine_test.go` (actual: 8). Card 24 claims "39 `e.Run(p, runDir, runDir)`-shaped call sites" in `internal/perchengine/run_test.go` (actual: 36). None of these block correctness — the compiler will surface every real site regardless — but the counts are meant to ground scope and are wrong. **Fix:** Recount and correct, or drop the specific numbers in favor of "every call site."
