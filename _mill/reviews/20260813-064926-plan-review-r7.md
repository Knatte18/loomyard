### [BLOCKING:scope] Batch 6 card 36 lacks the Context needed to resolve its own "provably a no-op" test
**Location:** batch 6 (`06-stuck-packages.md`), card 36.
**Issue:** Requirements says to "check with `fabricengine.WeftBranchName` and drop [the `git checkout -b`] only if it is provably a no-op," but `internal/fabricengine/clone.go` is not in Context. Reading it (verified) shows `CloneHub`'s weft-checkout helper already runs `git checkout -b <WeftBranchName(warpBranch)>` on the weft primary during clone (`clone.go` lines ~449-466). So `setupPreflightFixture`'s manual `git checkout -b` onto the same branch name is not merely redundant — it will fail outright with "branch already exists" once the fixture is a real hub. Without `clone.go` in Context, the implementer has no way to reach that conclusion and may leave the line in place, breaking every test that calls `setupPreflightFixture`.
**Fix:** Add `internal/fabricengine/clone.go` to card 36's `Context:` list, and state directly that the checkout line must be deleted (not merely "checked"), since `CloneHub` already performs it.
