## Findings

### [BLOCKING] Card 14's new --in-file integration test leaks a real supervised daemon
**Location:** Batch 5, Card 14 (`refs_integration_test.go`, `TestReferences_InFile_Integration`, case 1)
**Issue:** Case 1 calls `References` with `Registry: builtins()` (Go's entry has `HasNativeDaemon: true`) and `WorktreeRoot: repoRoot(t)`. After batch 4's flip this now routes through `ensureServer`->`ensureSupervised`, spawning a real lyx-owned daemon anchored at the *actual repo's* `.lyx/codeintel/go/` (not a temp dir), which `teardownConnection`'s `connKindSupervised` branch (ensureserver.go) deliberately never kills. This contradicts the card's own text — "this path spawns only gopls, never a lyx-owned daemon, so no state-file cleanup is needed" — which was true only pre-flip; the card depends on batch 4 (post-flip) but wasn't updated for the consequence. It also roots the daemon outside a temp dir, contrary to `supervised_integration_test.go`'s own stated isolation convention ("A fresh temp worktreeRoot per test run keeps runs isolated ... from any real worktree's own supervised daemon").
**Fix:** Set `WorktreeRoot: t.TempDir()` (keep `TargetDir: repoRoot(t)` for correct indexing) and add `t.Cleanup` daemon-reap logic mirroring card 13's new test, for both InFile subcases (case 2's ambiguity resolve also acquires a connection before erroring, so it spawns too).

### [BLOCKING] Pre-existing TestReferences_Integration now leaks an unreaped, relative-path daemon post-flip
**Location:** Batch 4 Card 12 (root cause) / Batch 5 (last chance to fix, same file it already edits), `refs_integration_test.go`'s existing `TestReferences_Integration` "live gopls references" subtest
**Issue:** This untouched, pre-existing subtest calls `References` with `Registry: builtins()` and no `WorktreeRoot` field set at all. Once card 12 flips Go's dispatch to supervised-primary, `WorktreeRoot=""` anchors the daemon state file/lock/socket at a *relative* `.lyx/codeintel/go/` path under the test binary's cwd (`hubgeometry.Layout.CodeintelDaemonStateFile` does `filepath.Join(WorktreeRoot, ...)` with no absolute-path guard), and the spawned supervised daemon is never killed (`connKindSupervised` teardown is a no-op by design). No card in batch 4 or 5 touches or reaps this test, unlike card 13's own new integration test which explicitly handles this exact case.
**Fix:** In batch 5 (which already edits this file for card 14), also update this subtest to set an isolated `WorktreeRoot: t.TempDir()` and reap the spawned daemon in `t.Cleanup`, mirroring card 13's teardown discipline.

### [NIT] Card 11's deadline-bounding instruction for reconnectUnderLock is underspecified
**Location:** Batch 4, Card 11 (`ensureserver.go`, `reconnectUnderLock`)
**Issue:** The card requires the implementer to "bound `reconnectUnderLock`'s dial retry by [the deadline]," but the proposed pure-helper signature takes only `ctx` (no deadline parameter) and is simultaneously told to mirror step 6's existing retry, which is itself deadline-unaware (blind 10×50ms `time.Sleep` loop) — leaving unclear how the deadline is meant to bound the retry itself, as opposed to only the after-return check.
**Fix:** Either drop the "bound the retry itself" language (the after-return `time.Now().After(deadline)` check already suffices per the card's own test-passing rationale) or explicitly specify wrapping `ctx` with `context.WithDeadline(ctx, deadline)` before calling `reconnectUnderLock`, with its retry loop checking `ctx.Err()`.

### [NIT] Card 7 overstates how similar refs'/definition's existing Long text is
**Location:** Batch 3, Card 7 (`cli.go`, `definitionCommand`'s `Long`)
**Issue:** The card says to "keep the wording consistent with the existing 'result set is complete and semantically resolved' sentence already in those Long blocks," but `definitionCommand`'s current `Long` reads "The result is semantically resolved by the language server, not text-matched" — it lacks the "complete"/"result set" phrasing `refsCommand`'s `Long` actually has.
**Fix:** Note the current wording differs per-command in the requirement (or explicitly instruct normalizing both to the same sentence) so the implementer doesn't assume a verbatim match that isn't there.
