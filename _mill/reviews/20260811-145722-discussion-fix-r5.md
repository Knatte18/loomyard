## Fixed

- `[NIT:decision]` "fabriccli cannot errors.As an unexported refusal type" (`20260811-145526`) — accurate: `*destructiveRefusal` is unexported (`destroy.go:62`), which is the same wall that forced `fabrictest` into substring matching (`fabrictest/refusal.go:46-49`).
  Round 3 gave the check *enum* an export disposition and silently left the refusal *type* without one.
  Added an exported accessor `fabricengine.RefusalOf(err error) (Refusal, bool)` with an exported `Refusal` value type carrying all four fields;
  `destructiveRefusal` itself stays unexported. Rejected exporting the struct directly (publishes a mutable pointer type when the envelope only needs its four values).

- `[NIT:scope]` "CLI-layer mutations and zero-result returns are unaccounted for" — accurate: `CloneAndWire` (`fabriccli/clone.go:29-67`) runs `configsync.ReconcileFabricAt`, `Bolt.Commit`, `Bolt.Push`, `WireJunctions` and `configsync.ReconcileAll` after `CloneHub`, returning a bare `fabricengine.CloneResult{}` at five failure sites;
  `runReconcile` (`fabriccli/fabric.go:568,588-621`) rewrites config and calls `Bolt.Commit`/`Bolt.Push`.
  Added a CLI-layer composition rule mirroring `push`/`sync`: the CLI owns a recorder, concatenates engine-then-CLI entries, and those five zero-result returns become populated returns.
  Clarified that scoping out `Bolt` as a *type* never scoped out the mutations made through it — its CLI call sites hand-record, while `Bolt`'s own signature stays untouched.

- `[NIT:scope]` "No Kind covers a pull/fetch advance; the partial rationale is false" — accurate, and the most consequential of the four.
  `Pull` sets `result.WeftPulled = true` (`pull.go:190`) and can then return `&PartialPullError{Stage:"unpushed-check"}` or `{Stage:"fetch"}` (`:193,197`) having created no commit and executed no gate primitive, so under the round-2 kind set the record was empty and `partial` would have been `false` while the weft worktree had genuinely advanced — this slice's own defect class, inside the verb that produced defect 1.
  Added a `repo_advanced` kind recorded at `PullWeft` success and at the warp advance, joined it to the worktree-root coverage set for the omission direction, and corrected the false rationale in `ok-semantics-and-error-path-fields` explicitly rather than quietly.

- `[NIT:scope]` "Non-verb result types the harness reads carry no stated record" — accurate: a cell drives `fabricengine.UnwireJunctions` (`junction.go:368`, from `verbs.go:960`), which returns the inner `UnwireResult`, not the verb's `UnwireVerbResult`.
  Stated that `UnwireResult` embeds the record too, plus the general rule that any result type a matrix cell reads carries it, and directed mill-plan to sweep `verbs.go`'s `Run` closures rather than working from the twelve-verb list.
