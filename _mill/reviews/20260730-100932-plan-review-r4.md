## Findings

### [NIT] CommitWeft's stale doc comment not relocated
**Location:** batch 1 / card 3
**Issue:** `CommitWeft`'s current large doc comment (staging tolerance, trailer, RecordCorrespondence detail) describes logic that moves into `commitWeftLocked`; Requirements never direct moving/trimming it, so the public wrapper keeps a doc comment describing internals it no longer performs directly, and gains no mention of `snapshotTags`.
**Fix:** Add a line to card 3 directing the detailed doc comment onto `commitWeftLocked` and leaving `CommitWeft` a short wrapper-doc plus a `snapshotTags` mention.

### [NIT] Untested "tags silently dropped on warp-only commit" behavior
**Location:** batch 3 / card 7, card 8
**Issue:** Card 7 documents that a warp-only `Fabric.Commit` silently drops any `snapshotTags` (no trailer, no error); card 8's assertion list (items 1–8) has no case exercising a warp-only call with non-empty `snapshotTags`, so a regression here (e.g. an errant attempt to trailer a bare warp commit) would go unnoticed.
**Fix:** Add one assertion to card 8 (or 10) calling `Fabric.Commit` with warp-only files and non-empty `snapshotTags`, asserting no error and no trailer on the warp commit.

### [NIT] opts.SkipPush ignored by Fabric.Commit's async push, not called out in docs
**Location:** batch 3 / card 7; batch 5 / card 14
**Issue:** `Fabric.Commit`'s push guard is purely "did anything land," and `SpawnDetachedPush` gates only on `WEFT_SKIP_GIT`/`WEFT_SKIP_PUSH` env vars — `opts.SkipPush` (a field on the very `SyncOptions` the method takes) is silently ignored for the async push. Card 14's doc requirement calls out `opts.SkipGit`'s weft-scoped narrowing but never mentions `opts.SkipPush` being ignored too, which is the more surprising half for a caller of a new public Go API.
**Fix:** Add a sentence to card 14's doc.go requirement stating `opts.SkipPush` is also not consulted by the async push (env-var gating only), mirroring the `SkipGit` sentence already required.
