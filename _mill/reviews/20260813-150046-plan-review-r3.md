## Findings

### [BLOCKING:design] add.go's HEAD-probe site misclassified as a plain merge
**Location:** batch 4 / card 20 (`internal/fabricengine/add.go`, `Add`, the `rev-parse --abbrev-ref HEAD` call at the current lines ~106-113).
**Issue:** The site's exit-path guard is not `exitCode != 0` alone — it is the compound `exitCode != 0 || strings.TrimSpace(stdout) == "HEAD"`, where the second disjunct is a *successful* git call (detached HEAD, nil error). Card 20 lists this as one of the "five... plain two-message merges taking default-merge-rule," but default-merge-rule's own stated scope ("a site where `err != nil` and `exitCode != 0` are separate guards") does not cover a guard that also fires on success. A mechanical `if err != nil { return "...detached HEAD or unborn branch: %w", err }` would misattribute an unrelated exec-level failure to "detached HEAD or unborn branch," and cannot even be written that way once `stdout == "HEAD"` is folded in, since that arm has no error at all.
**Fix:** Call this out explicitly (like the adjacent branch-exists probe in the same card) as needing `errors.As` recovery plus a separate `stdout == "HEAD"` check, not `default-merge-rule`.

### [NIT:consistency] card 12's rationale contradicts card 7's HasUnpushed migration
**Location:** batch 2 / card 12 (`cmd/lyx/gitrepoboundary_test.go`).
**Issue:** Card 12 states "after migration only Pull, Fetch, and HasUnpushed still call `r.run`," but card 7 explicitly migrates `HasUnpushed` to `r.runChecked`. Per the overview's pinned-raw-count decision, only `Pull` and `Fetch` remain raw in `internal/gitrepo` — the "other nine" methods figure is then also off by one (should be ten of twelve).
**Fix:** Correct the rationale to "only Pull and Fetch still call r.run... the other ten." Does not change the required guard code (union of `run`+`runChecked`, 12 pinned names unchanged), only the explanatory prose.

### [NIT:design] card 35 asks to replace prose that isn't in CONSTRAINTS.md today
**Location:** batch 8 / card 35 (`CONSTRAINTS.md`, `## gitrepo Client Boundary Invariant`).
**Issue:** Card 35 says to "replace the 'exactly one `gitexec.` occurrence' claim" in this section. Verified against the current file: that phrase does not appear anywhere in `CONSTRAINTS.md`'s gitrepo Client Boundary Invariant (or anywhere else) — it exists only as `cmd/lyx/gitrepoboundary_test.go`'s own header-comment claim ("exactly one `gitexec.RunGit` call site... in the package's non-test source"), which card 12 already updates separately.
**Fix:** Reword to "add the two-call-expression assertion the repaired guard now makes" rather than "replace," since there is nothing to replace in the doc.

### [NIT:design] wrapProbeError's dead nil-cause branch after migration
**Location:** batch 5 / card 23 (`internal/fabricengine/warpprobe.go`, `wrapProbeError`).
**Issue:** Card 23 keeps a `cause == nil` branch in the re-signatured `wrapProbeError`, justified as "what keeps `op` load-bearing rather than an unused parameter." After migration, all seven call sites only ever invoke `wrapProbeError` from inside an `err != nil` branch, so `cause` is always non-nil in practice — the nil-branch (and therefore `op`'s only real use) is dead code, making the stated justification inaccurate.
**Fix:** Either note the branch is deliberately defensive/unreachable-by-construction, or drop it and simplify the signature.
