### [BLOCKING:scope] Card 10's Context omits internal/lyxcwd/anchor.go, the file its own Requirements depend on
**Location:** batch 03-preflight-lift.md, Card 10
**Issue:** Card 10's Requirements instruct rewording the comment on `Check`'s non-`ErrNotAGitRepo` branch to say the residual branch is "reachable only through the anchor gate — `lyxcwd.ErrCwdOutsideAnchor` and `lyxcwd.ErrStaleAnchorMarker`." ### [BLOCKING:design] The mandated "reachable only through" comment is itself inaccurate — a third path exists
**Location:** batch 03-preflight-lift.md, Card 10 (echoed by Card 12's doc.go requirement, "per card 10")
**Issue:** `internal/lyxcwd/anchor.go`'s `readRecordedAnchor` has a third error path beyond the two named: when the recorded `.lyx-anchor` marker exists, is non-empty, but fails `ValidateAnchorRel` (e.g. an absolute or escaping path), it returns `fmt.Errorf("recorded anchor at %s is unusable: %w", board, validateErr)` wrapping `ErrInvalidAnchor` — not `ErrStaleAnchorMarker`, not `ErrCwdOutsideAnchor`, and not `ErrNotAGitRepo`. `resolveCore` propagates this directly from `Resolve(cwd)`. Card 10's own stated purpose is to replace a false comment (today's "e.g. the git subprocess itself failed to spawn" claim) — but the replacement text it prescribes is itself incomplete/false, for exactly the reason Finding 1 above identifies: the file that would reveal this third path isn't in Context.
**Fix:** Reword the required comment to name all three reachable causes (`ErrCwdOutsideAnchor`, `ErrStaleAnchorMarker`, and a recorded-anchor `ValidateAnchorRel` failure/`ErrInvalidAnchor`), or phrase it as "the anchor-resolution path" generically rather than enumerating an exhaustive two-sentinel list.
