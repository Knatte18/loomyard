### [BLOCKING:design] Roadmap-mandated sole-parser invariant dropped
**Location:** batch 6 Batch Scope + card 23
**Issue:** `manifest/roadmap.md:17` states, for this exact item, "This item is where a sole-parser invariant for the recipe format belongs, added to `CONSTRAINTS.md` in that same commit as a review obligation" — batch 6's batch-local decision says no new invariant is added and card 23 says "Make exactly two edits… Change nothing else in the file."

**Fix:** add the recipe-format sole-parser invariant to `CONSTRAINTS.md` as a third card-23 edit, modelled on the Planparser Sole-Parser Invariant, or record an explicit decision overriding the roadmap.

### [BLOCKING:scope] `shedrecipe.Env`'s declaring file is in no card's Context
**Location:** cards 3, 5, 7, 15, 16, 18
**Issue:** every card that fills or documents `shedrecipe.Env` lists `internal/shedrecipe/env.go` in `Context:` — that file declares only `requireAbsRoot`/`requireSeam`. `Env` (and `Constructor`/`Config`) are declared in `internal/shedrecipe/recipe.go`, which appears in no card's `Context:` or `Edits:` until batch 6 card 26.

**Fix:** add `internal/shedrecipe/recipe.go` to the `Context:` of cards 3, 5, 7, 15, 16, 18 and `internal/shedbuild/build.go` to card 7.

**Location:** batch 2 / batch 4 / batch 5 / batch 6 Batch Tests
**Issue:** `go build ./...` never compiles `_test.go` files, so the stated boundary check cannot prove what each batch claims. Batch 6's comment edit to `internal/preflightshed/preflight_test.go` is covered by neither its `verify:` nor the build.
**Fix:** add `./internal/loomrecipe/...` to batch 5's `verify:` and `./internal/preflightshed/... ./internal/shedrecipe/... ./internal/shedcheck/...` to batch 6's, and restate the boundary claim as `go vet`/`go test`, not `go build`.
