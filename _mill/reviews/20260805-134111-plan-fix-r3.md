# Plan fix — round 3

Source review: `_mill/reviews/20260805-134111-plan-review-r3.md` (holistic, REQUEST_CHANGES, 4 BLOCKING + 3 NIT, reviewer `opushigh`).

Three of the four blocking findings are one defect wearing three faces: a card that *declares* a geometry token, or *deletes* a method, was scheduled in a different batch from the guard row or the call-site edits that keep the tree compiling. The plan already carried a Shared Decision saying the guard is staged "token by token, in lockstep with each owner" — the batch files simply did not honour it. The fix applied here is stronger than the one the review proposed: rather than splitting the guard card across batches, **the card that declares a token now registers its own ownership row in the same card**, which is what makes the plan's own per-card independence rule ("ett og ett card skal gå") true rather than aspirational.

## Fixed

- "[BLOCKING] Batch 1's green-tree gate cannot pass — guard rows lag owners". Verified against the guard itself: `enforcement_test.go:219-226` policices `-weft` and `_lyx` among eight tokens, `:281-302` is the string-const-declaration context, and `:420` allowlists exactly one directory. Card 1's `const Suffix = "-weft"` and card 2's `LyxDirName = "_lyx"` are both production const declarations outside it, and batch 1's `verify` runs the untagged `go test ./...` that executes the guard — so batch 1 was red as sequenced. Card 1 now owns the allowlist-to-map conversion (adding `internal/hubgeometry/enforcement_test.go` to its `Edits:`, seeding `-weft` → `internal/weftname` with every other token reproducing today's behaviour on `internal/hubgeometry`), and card 2 flips the `_lyx` row to `internal/configengine` plus the transitional `internal/hubgeometry` co-owner for the private `lyxDirName` const it leaves behind. Both use pre-rename paths, since batch 1 runs before batch 2's `git mv`. Card 19 keeps only what is genuinely its own: retargeting the surviving directory *values* from `internal/hubgeometry` to `internal/lyxcwd`. Batch 4's `## Batch Tests` was updated to match.
- "[BLOCKING] Card 4 deletes `(*Layout).WorktreePath(slug)` with live in-package test callers unlisted". Verified all seven on disk — `hubgeometry_test.go:130,423,449,572`, `pattern_test.go:106`, `weft_test.go:131,299`. The card enumerated only the four production in-module callers, so package `hubgeometry` would not have compiled. Flagged `hubgeometry_test.go:130` specifically — it is the one site whose *subject* is the deleted method, so the implementer is told to weigh whether the assertion survives card 5's no-arg accessor.
- "[BLOCKING] Batch 5 moves the `_pattern` declarer but not its ownership row". Verified: card 25 declares `const DirName = "_pattern"` in `internal/pattern` while the row still named `internal/lyxcwd`, and batch 5's `verify` runs `go test ./internal/lyxcwd/...`, which executes the guard. Card 25 now moves the row itself, in the same card, per the rule above. It does **not** add `fabricengine` as a second owner, because nothing in card 25 puts a `_pattern` literal there — batch 6 adds that row when it creates the reason for it. Card 29's zero-diff gate was corrected: it claimed the guard passes "unchanged", which is no longer true, so it now asserts the precise, narrower property it actually owns — that `_pattern`'s row is the *only* one this batch touched, and that no new `_lyx` owner appeared.
- "[BLOCKING] Card 32's `HostLyxLinkHere` disposition and Edits list are wrong". Verified: the card said "delete it if card 32 finds no in-package caller", leaving the disposition to be discovered at implementation time, and seven live callers exist. The review found six in three files; there is a seventh, `junction_pattern_integration_test.go:385`, which is a func value in a table (`func(l *hubgeometry.Layout) string`) and needs its parameter type changed as well as its body — that file was already in the card's `Edits:`, the other three were not. The disposition is now decided in the plan rather than deferred: relocate as unexported `hostLyxLinkHere(l)` in `fabricengine/junction.go`, with all seven call sites named and both retarget shapes spelled out.
- "[NIT] Card 25 contradicts itself on `internal/pattern`'s import set". Verified: `leaf_enforcement_test.go:23-24` allowlists only the cwd module, and none of `DirName`/`Dir`/`File`/`FileHere` needs a config path. Dropped `internal/configengine` from the sentence.
- "[NIT] Card 31 both relocates and deletes `WeftRaddleDir`, and cites the wrong card". Both verified. Removed `weftRaddleDir(l)` from the re-declare list and added a clause saying its absence is deliberate, so the next reader does not restore it. Corrected the cross-reference from card 24 to card 30.
- "[NIT] ~20 files keep comment-only `hubgeometry` references no card touches". Verified and enumerated precisely: 48 files name `hubgeometry`, of which 36 do so without importing it; excluding the module's own files leaves 23 that no card in the plan mentions at all.
