## Findings

### [BLOCKING:consistency] raw "_lyx" geometry literal in hub_test.go violates geometry-through-accessors
**Location:** `internal/fabricengine/fabrictest/hub_test.go:124`
**Issue:** `filepath.Join(h.BoardDir(), "_lyx", "config", "fabric.yaml")` spells `_lyx` as a raw string literal inside a `filepath.Join` argument. The plan's `geometry-through-accessors` Shared Decision ("Applies to: all batches") explicitly bans spelling `_lyx`/`.lyx`/`_board`/etc. as a literal in a `filepath.Join` argument anywhere in `fabrictest`, precisely because `fabrictest` deliberately carries no `geometryTokenOwners` row and `TestEnforcement_GeometryLiterals` excludes `*_test.go` files by design, making this a review-only backstop rather than a machine-checked one.
**Fix:** Use `lyxdirs.LyxDirName` (already named as an available accessor in the Shared Decision's own list) in place of the literal `"_lyx"`.

### [NIT:consistency] hardcoded "_lyx" porcelain-line literal in states_test.go
**Location:** `internal/fabricengine/fabrictest/states_test.go:150-152`
**Issue:** `allowed = "?? _lyx/"` hardcodes the `_lyx` token as a string const value to match a `git status --porcelain` line, the same token class the geometry-through-accessors decision names, even though this is a comparison string rather than a path-join argument.
