## Findings

### [BLOCKING:scope] Card 13's new test names `Seed` from a file absent from Context/Edits
**Location:** batch 3, card 13 (`internal/loomshed/loomshed_test.go`)
**Issue:** Requirements say to "seed through the production `Seed`" but `Seed` lives in `internal/loomshed/seed.go`, which is listed in neither card 13's `Context:` nor `Edits:` — a Context-completeness violation. Worse, `seed.go`'s own doc comment pins `Seed` to always write `CurrentProducer: NamePreflight, State: StateRunning`; it has no parameter to produce `current_producer: NameFinalize, state: done` as the card asks for. Achieving that end state needs a second write (e.g. a `state.UpdateJSON` patch, the pattern `resume_test.go`'s `resetCurrentProducer` already uses) that the card never names.
**Fix:** Add `internal/loomshed/seed.go` to card 13's `Context:`, and name the two-step mechanism explicitly (call `Seed`, then patch `current_producer`/`state` via a lock-cooperating updater) rather than implying `Seed` alone reaches the target state.

### [NIT:consistency] Card 13 collides with the pre-existing `TestNew_PassesShedValidation`
**Demoted-from:** BLOCKING
**Location:** batch 3, card 13 (`internal/loomshed/loomshed_test.go`)
**Issue:** `loomshed_test.go` already contains `TestNew_PassesShedValidation` (verified in source), whose own doc comment states its purpose almost verbatim: "Drive Run to exercise (*Shed).validate() indirectly." Card 13 says "Add a test asserting that the `*shedengine.Shed` returned by `New` passes `shedengine`'s own validation" with a different seed shape (current_producer=Finalize/done vs. the existing test's Preflight/running→RunBlocked), never mentioning the existing test. The obvious implementation name collides (duplicate `func` = compile error), or an implementer silently overwrites/renames the existing scenario, discarding its coverage undocumented.
**Fix:** Name the existing test explicitly and state its disposition — e.g. "leave `TestNew_PassesShedValidation` as-is; add a second test named `TestNew_FinishedShedPassesValidation`" (or similar), so the two don't collide.

### [NIT:design] New OnStuck/Segment check's ordering vs. the existing OnStuck-existence check is unspecified
**Location:** batch 1, card 3 (`internal/shedengine/validate.go`)
**Issue:** Requirements order the two new `OnDone` rules explicitly but say nothing about where `p.OnStuck != "" && segmentByName[p.OnStuck] != p.Segment` sits relative to the pre-existing `p.OnStuck != "" && !seen[p.OnStuck]` check in the same loop. If the new rule runs first, an `OnStuck` naming a nonexistent producer (with both `Segment` fields empty by zero-value coincidence) surfaces the misleading "different Segment" message rather than "names no producer in the list."
**Fix:** State that the pre-existing not-found check runs before the new same-Segment check.
