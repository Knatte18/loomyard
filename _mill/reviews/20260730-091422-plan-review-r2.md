## Findings

### [BLOCKING] Card 3 uses goquery before go.mod declares it
**Location:** Batch 1 / Card 3 (htmltext.go) vs Card 6
**Issue:** Card 3's `htmlToText`/`stripToBodyText` require `goquery.NewDocumentFromReader`, but Card 3 has `Edits: none` (no go.mod/go.sum) and never runs `go get`. Card 6 then states "First run `go get github.com/go-shiori/go-readability github.com/PuerkitoBio/goquery` ... this card is where those deps are first imported" — false, Card 3 (three cards earlier) already imports goquery. Go modules default to `-mod=readonly`, so Card 3's own commit will fail `go build`/`go test` with an unresolved-import error, contradicting the Batch Scope's explicit "keeping every intermediate commit buildable with the stdlib-only cards" goal, and misleading whoever implements Card 6 into thinking goquery is newly introduced there.
**Fix:** Add `go get github.com/PuerkitoBio/goquery` plus a `go.mod`/`go.sum` `Edits:` entry to Card 3, and drop goquery from Card 6's "first imported" `go get` line (Card 6 then only newly imports go-readability).

### [NIT] fetch_test.go coverage gap on double-fallback-failure
**Location:** Batch 1 / Card 6
**Issue:** The enumerated `fetch_test.go` scenarios cover "browser stub triggered" for the <100-char-readability branch and the no-extraction branch, but never assert the outcome when that same stubbed browser also returns empty (fetchPage's documented behavior is to fall back further: return the short readability text, or the final "Could not extract readable content" message, respectively).
**Fix:** Add the two browser-also-empty scenarios to Card 6's `fetch_test.go` coverage list.

### [NIT] Lock-age staleness path has no test or documented manual check
**Location:** Batch 2 / Card 9
**Issue:** discussion.md's build-on-first-run decision added lock-age staleness recovery specifically for the SIGKILL-orphaned-lock case (a prior review round's fix), but Card 9's `selftest.sh` neither exercises this path nor lists it among the explicitly-deferred manual checks (only go-missing and failed-build are called out as manual there).
**Fix:** Either add a `selftest.sh` case that backdates a fake `.build.lock` dir's mtime past the ~120s threshold and asserts `run.sh` proceeds to rebuild rather than waiting out the full timeout, or add this path to the manual-checks list alongside go-missing/failed-build.

## Verdict

REQUEST_CHANGES
Card 3's undeclared goquery dependency breaks intermediate-commit buildability; two minor test-coverage gaps also noted.
