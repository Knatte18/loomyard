### [BLOCKING] Card 10 breaks existing test TestAdd_RejectsReservedHubNameSlug
**Location:** batch 2 / card 10 (`internal/fabricengine/add.go:119`)
**Issue:** Card 1 removes `_lyx`/`_pattern` from `hubgeometry.HubReservedNames()`. Card 10 changes `add.go:119` to `IsReservedHubName(slug, t.cfg.Dirs())`. The existing `TestAdd_RejectsReservedHubNameSlug` (`add_test.go:124`, sub-case `"LyxDir"`) constructs `fabricengine.NewTopology(fabricengine.Config{})` — an empty `Config`, so `t.cfg.Dirs()` is empty — meaning `IsReservedHubName("_lyx", [])` now returns `false` and this pre-existing test fails. Neither card 10 nor card 14 (the only cards touching `add.go`/`add_test.go`) updates this sub-case; card 14 only *adds* new coverage. Batch 2's own `verify:` runs `./internal/fabricengine/`, so this test failure is not deferred to batch 3 — batch 2 fails its own stated gate, and `go test ./...` (the done_gate) fails permanently until fixed.
**Fix:** Update `TestAdd_RejectsReservedHubNameSlug`'s `"LyxDir"` case (or the whole test) to construct the `Topology` with a non-empty `Config{Pathspec: "_lyx _pattern"}` so `_lyx` stays rejected via the injected set, in the same card that changes `add.go:119` (card 10), not deferred to card 14.

### [BLOCKING] PairInSync vs checkJunctionHealth diverge on config-load failure, breaking Preflight's contract
**Location:** batch 2 / card 8 (`drift.go`) vs card 9 (`reconcile.go`)
**Issue:** Card 9's `checkJunctionHealth` treats a `fabric.yaml` load failure as a graceful reason string (`false, "cannot load fabric.yaml: ..."`) specifically "so an operator is not misdirected toward junction repair." Card 8's `PairInSync` — documented as the Here-anchored twin of `checkJunctionHealth` — treats the *same* failure as a hard `error` (`false, "", fmt.Errorf(...)`). `loomengine/preflight.go:120-123` (listed in card 8's own Context) propagates that `err` straight into `return Report{}, err` — an infra-escalation the package's own docstring reserves for "could not determine an answer at all," not for a determined "not initialized / bad config" state. This is a new failure mode (today's hardcoded `_lyx`/`_pattern` never needed config) that silently converts a graceful Preflight report into a hard caller-must-escalate error for a corrupted/missing `fabric.yaml`.
**Fix:** Make `PairInSync`'s config-load failure a `(false, "cannot load fabric.yaml: ...", nil)` reason (mirroring card 9), not a hard error, or explicitly justify and document the divergence and its Preflight consequence in the Shared Decisions.
