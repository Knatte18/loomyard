### [NIT:consistency] applyLayoutLocked's new live-box query bypasses its own documented skip guards
**Demoted-from:** BLOCKING
**Location:** batch 1 / card 2 (apply.go)
**Issue:** The prescribed call site is `e.planLayout(st, live, e.liveBoxLocked())`, evaluated at the top of `applyLayoutLocked` — before the `len(live) < 2` and `!anyPlacedStrand(...)` skip guards. `liveBoxLocked` is a real tmux `display-message` round trip, so it now fires unconditionally on every call, including the degenerate paths the function's own (unrevised) doc comment says "skip both tmux calls entirely." This also adds an extra round trip per iteration of `Resume`'s per-launch `reconcileApplyPersistLocked` reapply loop, which the plan neither acknowledges nor defers. Card 6 (batch 2)'s `AttachArgv`, by contrast, deliberately computes its skip guards *before* planning — the two call sites now disagree on ordering with no stated reason.
**Fix:** Either compute the live box only after the skip guards pass (restructure `applyLayoutLocked` so `liveBoxLocked()` is not evaluated on the early-return paths), or explicitly amend the doc-comment sentence "it skips both tmux calls entirely" so it no longer contradicts the new unconditional query, and state the added-round-trip tradeoff in Card 2's requirements.
