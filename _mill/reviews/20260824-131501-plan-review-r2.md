## Findings

### [BLOCKING:design] Card 12 inverts the actual behavior of the test it edits
**Location:** batch 03-consumer-fixtures, Card 12 (websterengine template tests)
**Issue:** The card says the target test "asserts the rendered fork prompt carries the `## Rename mechanic` section regardless of whether the batch has a rename-bearing card" and "the rendered output must still carry the section either way." The actual test, `TestRenderForkPrompt_OmitsRenameMechanic` (`internal/websterengine/template_test.go:753-771`), asserts the exact opposite via `requireNotContains(t, text, "## Rename mechanic")` — the fork prompt never carries that section, by the fork-context-hygiene Shared Decision (that content is already in Master's inherited context; see the file's own `requireNotContains` doc comment at lines 218-222, which lists `## Rename mechanic` among concepts deliberately excluded from the fork prompt).
**Fix:** Correct Card 12's prose to state the test proves the section's *absence* regardless of rename-bearing status. The "keep the test's own assertion unchanged" instruction happens to be safe as written, but the surrounding false premise risks an implementer "fixing" `requireNotContains` to `requireContains` to match the (wrong) prose, breaking a passing test.

### [BLOCKING:scope] Card 10 leaves a stray format-3 fixture in `sections_test.go` that trips the plan's own Sweep 1
**Location:** batch 02-planparser-tests, Card 10 (normalization and plan-section tests)
**Issue:** `internal/planparser/sections_test.go` has two tests. Card 10 says only to update `TestParsePlan_GoldenFixture_PlanLevelSections`; `TestParsePlan_PlanLevelSections_AbsentAreEmpty` is explicitly left untouched ("keep both tests"). That second test builds its own inline overview/card fixture containing the literal `format: 3` and the full set of format-3 field labels (`**Context:** none`, `**Edits:** none`, etc.) — it is not a deliberate `format-unrecognized` test (it only calls `ParsePlan`, never `Validate`), so it does not qualify for either exemption Sweep 1 (re-run by Card 26) allows for a remaining `format: 3`/`**What:**` hit. Card 26's own criteria call this "a missed carrier that must be fixed before this card is committed," but no card's scope covers fixing it, and Card 26 changes no files.
**Fix:** Add to Card 10's requirements: update `TestParsePlan_PlanLevelSections_AbsentAreEmpty`'s inline overview/card fixture to `format: 4` and a minimal format-4 card body (e.g. a single type label plus `**Intent:**`), so Sweep 1 is clean without reopening an already-committed card.
