### [BLOCKING] initcli.go Long help text still tells users to run deleted `lyx warp` commands
**Location:** `internal/initcli/initcli.go:39,42-43`
**Issue:** `lyx init`'s cobra `Long` text reads "It wires cwd-keyed warp junctions..." and "A weft pairing must already exist (run 'lyx warp add' or 'lyx warp clone' first)." Batch C deregisters `lyx warp`/`lyx weft` from the cobra root, so this help now instructs the operator to run commands that no longer exist. This file is not in any batch's Edits list, so the cutover missed it. CONSTRAINTS.md's CLI/Cobra Invariant states "stale help is a review-blocking defect."
**Fix:** Rewrite to "wires cwd-keyed fabric junctions" and "run `lyx fabric add` or `lyx fabric clone` first".

### [BLOCKING] init.go's own error message tells users to run deleted `lyx warp` commands
**Location:** `internal/initengine/init.go:62`
**Issue:** `fmt.Errorf("no weft pairing — run \`lyx warp add\` or \`lyx warp clone\` first")` is the exact user-facing text emitted on the "no weft pairing" error path. Card 1 explicitly scoped its edit to the `WireJunctions` call and one step-comment only ("Do not change any other call"), leaving this string un-rewired even though `lyx warp` no longer exists post-cutover (batch C). This is not a comment — it is emitted directly to the operator via the JSON error envelope, actively misleading them toward dead commands.
**Fix:** Update the message to `lyx fabric add` / `lyx fabric clone`.
