## Findings

### [BLOCKING:design] New profile test can boot live substrate or assert nothing
**Location:** batch 2, card 7 (`TestRunVerb_RelativeProfileResolvesAgainstSeamCwd`)
**Issue:** To reach `os.ReadFile(cliwire.ResolveToldDir(c.cwd, profilePath))` the standalone pre-run must *succeed* (`run.go:128` returns early on `clihelp.ShouldAbort`), after which `run.go:149-173` decodes the profile and, on success, calls `c.reedUp()` → `reedEngine.Up()` → a live tmux/reed boot from an untagged tier-1 test; if instead wiring fails, the card's only assertion ("output does not contain `read --profile`") passes vacuously without ever exercising the resolution it claims to pin. The card's premise that the invocation "is expected to fail later, at wiring or engine construction" is wrong — wiring runs in `PersistentPreRunE`, before `RunE`.
**Fix:** Pin the fixture so the flow stops at `decodeProfile` (a file that fails the strict decode) and assert the decode error naming that file positively, stating that `c.reedUp` must never be reached.

### [BLOCKING:scope] Card 7's profile test omits the mandated state-home redirect
**Location:** batch 2, card 7 (`TestRunVerb_RelativeProfileResolvesAgainstSeamCwd`)
**Issue:** The card specifies only "`c.cwd` pointed at a `t.TempDir()`" and "do not `os.Chdir`"; driving `run` through `RunCLIIn` reaches the real `standalonestate.Derive` and the real `stencilstore.Reconcile`, so without `XDG_STATE_HOME`/`LOCALAPPDATA` redirected the untagged test seeds a stencils tree and a trace sink into the developer's actual state home — contrary to the overview's "every moved test stays tier 1" decision (which mandates both env redirects and no `t.Parallel()`), and contrary to `internal/burlercli/cli_integration_test.go`, which sets both and is `//go:build integration` for exactly this reason.
**Fix:** Require `setStandaloneStateRoot`-equivalent redirection of both variables and no `t.Parallel()` in the card's Requirements, as cards 6 and 7's `TestWireModule_DescriptorIsVerbatim` already do.

### [NIT:consistency] `Module.Name` doc comment contradicts the no-caller-names rule
**Location:** batch 1, card 3
**Issue:** The `Name string` bullet instructs writing `("webster", "burler")` into the field's doc comment, while the same card and card 1(c) state that no production file in `internal/cliwire` names either caller, and forbid the other four fields from quoting either value.
**Fix:** Either state the `Name` carve-out explicitly, or drop the concrete values from that doc comment.

### [NIT:consistency] `cmd/lyx/prerunlogging_test.go` left un-retargeted and overstated
**Location:** overview (verify rationale), batch 1/2 `## Batch Tests`, cards 6-7
**Issue:** That file's header and failure message say "webstercli's and burlercli's `wireStandalone`, which now redirect the durable trace sink … the moment `standalonestate.Derive` returns" — prose the move invalidates the same way cards 6/7 retarget `wireStandalone`'s own comments — and it in fact asserts only that root's pre-run emits no `Info`/`Warn` before `seedStencils`, not "the standalone durable-sink redirect".
**Fix:** Either add the file to a card's retarget list, or soften the three verify justifications to what the test actually guards.

### [NIT:consistency] Card 5 prescribes a helper it then says nothing calls
**Location:** batch 1, card 5
**Issue:** `hash8For` is required as a declared helper, then the very next bullet says every `ResolveStandalone` case calls `hash8AndStateDir` "not `hash8For`", leaving a dead helper Go will not flag.
**Fix:** Drop `hash8For` unless a named case uses it.
