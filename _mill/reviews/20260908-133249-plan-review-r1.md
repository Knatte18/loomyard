## Findings

### [BLOCKING:scope] Card 7 silently deletes burler's R4-26 wiring composition test
**Location:** batch 2 / card 7 **Issue:** Card 7 tells the implementer to delete the whole `TestResolveStandaloneTarget_LiftsToRepositoryRoot` function in `internal/burlercli/wiring_test.go`, but that function's `SubdirectoryWiresOntoTheRootsOwnStateDir` subtest (lines 655-673) is not a pure-function test at all — it calls `c.wire(...)` and asserts `c.stateDir` against the root's own derived state directory, i.e. it is burler's own R4-26 end-to-end wiring-composition regression test. Webster's exact analog, `TestWireStandalone_SubdirectoryOfRepositoryWiresLikeItsRoot`, is a top-level test explicitly kept by card 6. Card 7's deletion list and keep list never mention this subtest, so it is lost with no replacement, unlike webster's. **Fix:** Card 7 should either promote `SubdirectoryWiresOntoTheRootsOwnStateDir` to its own retained top-level test (mirroring webster's), or explicitly justify why burler needs no such composition coverage.

### [NIT:consistency] Import-drop lists in cards 6/7 omit likely-orphaned `fmt`/`path/filepath`
**Location:** batch 2 / card 6 and card 7 **Issue:** Both cards enumerate imports to drop from `wiring.go` (`os`, `runtime`, `strings`, `standalonestate`, `stencilstore`, `buildinfo`, `contracts/stencils`, conditionally `logger`) but never mention `fmt` or `path/filepath`. Tracing the surviving function bodies (`wire`/`wireHub`/`wireStandalone`/`wireModule`), `path/filepath` appears unused in webster's post-rewrite file, and both `fmt` and `path/filepath` appear unused in burler's (whose `wireModule.Plan` is nil, so no `fmt.Sprintf`-built message is needed there). An unused import is a hard Go compile error. **Fix:** Note in both cards that the parenthetical list is a non-exhaustive example and the whole import block must be grep-verified, not just the named entries; the existing "verify each removal by grepping" sentence already implies this but should say so explicitly to avoid a wasted implementation cycle.

### [NIT:consistency] `MissingPlanRefusal`'s second parameter name doesn't match its actual argument
**Location:** batch 1 / card 3, batch 1 / card 4 **Issue:** `PlanRules.MissingPlanRefusal func(planDir, defaultPlanDir string) string` names its second parameter `defaultPlanDir`, but `ResolveStandalone` (card 4) calls it with `recourse`, which is `planDir` itself (not a separate default) whenever the plan directory was not overridden — so the parameter name is misleading in that branch. **Fix:** Rename the type's second parameter to something branch-neutral, e.g. `recourse`, matching the call site's own local name.
