## Findings

### [BLOCKING] Unwire's WeftContent port drops a branch, contradicting its own "verbatim" claim and Card 30's test
**Location:** Batch 6, Card 23 (`init-dissolution-and-unwire`)
**Issue:** Card 23 claims to port `undo.go:122-159` "verbatim in behavior" but its own two-branch paraphrase ("if weft worktree absent → not_present; else RemoveAll(...) → cleared") collapses `undo.go`'s actual three-way branch (verified: weft-worktree-absent → `not_present`; weft-worktree-present-but-`_lyx`-absent → **also** `not_present`; `_lyx`-present → `cleared`, at undo.go:122-138). A raw-adopted worktree (weft exists dormant, `_lyx` never materialized — `reconcile.go`'s `createDormantWeftForRawHost` path) would report `WeftContent=="cleared"` under the simplified paraphrase, contradicting Card 30's own expectation that a "never-wired host" reports `WeftContent == "not_present"`.
**Fix:** Restore the nested `os.Stat(l.WeftLyxDirFor(slug))` check before `RemoveAll` so `Unwire` reports `"not_present"` whenever `_lyx` itself never existed, independent of whether the weft worktree exists — matching undo.go's actual three-way logic, not the card's simplified restatement of it.

### [NIT] Card 33's docs/overview.md:170 edit target contains no "lyx init" text to remove
**Location:** Batch 7, Card 33 (`docs-and-sandbox-suites`)
**Issue:** Card 33 instructs dropping a "`lyx init`" mention at `overview.md:170` (the `config` module bullet), but that line's actual text (verified) has no "lyx init" substring at all — a grep of the file shows "lyx init" occurs only at lines 168, 181, and 188. Only line 181 (the `loom` bullet, "…reconciles via `lyx init` / `lyx config reconcile`.") actually needs this edit.
**Fix:** Drop the erroneous line-170 sub-instruction from Card 33; keep only the line-181 edit.

### [NIT] Stale `internal/initengine` reference in configsync.go survives both the fabric-skip batch and the init-deletion sweep
**Location:** Batch 3 Card 11 / Batch 6 Card 28
**Issue:** `configsync.go:99`'s doc comment ("…so initengine's `Applied && len(Added) > 0 && len(Removed) == 0` 'created' heuristic still fires correctly") names `internal/initengine`. Card 11's conditional instruction ("update … if it still describes fabric-per-worktree behavior") doesn't fit this comment (it describes the seed-only-module branch generally, not fabric), and Card 28 (batch 6's init-reference sweep) does not list `internal/configsync/configsync.go` in its Edits — so after `internal/initengine` is deleted this comment dangles, naming a package that no longer exists.
**Fix:** Add `internal/configsync/configsync.go` to Card 28's Edits and reword the line-99 comment to drop the `initengine` reference.

### [NIT] Card 9's stale-removal placement across Reconcile's outcome branches is underspecified
**Location:** Batch 2, Card 9 (`reconcile-declarative-convergence`)
**Issue:** Card 9 says to add stale-removal "after the add-missing wiring for a healthy-or-repaired pair," but `Reconcile` (reconcile.go:104-178) has five possible per-pair outcomes (weft-recreated, junction-repointed, already-healthy, raw-adopted, unmanaged-reported). It is not stated whether stale-removal also runs for the weft-recreated/raw-adopted branches (where no junction was just wired this iteration), leaving the implementer to guess the scope.
**Fix:** State explicitly which of Reconcile's outcome branches the stale-removal step runs after — e.g. "unconditionally, for every pair with a resolved hostLayout" vs "only inside the weft-worktree-exists branch."
