## Fixed

- **[BLOCKING] "run.sh's build-lock never releases on the real (non-BUILD_ONLY) run path"** — `exec` replaces the process image, so the `EXIT` trap never fires on the exec branch, orphaning `.build.lock` after every real run. Card 8's `run_or_exit` now releases the lock explicitly (token-checked `rm -rf "$LOCK"`) BEFORE the exit/exec, making it correct on both branches; the token check keeps it a safe no-op on the reuse path. The `EXIT` trap is retained only as a backstop for the error-exit paths (toolchain-missing, build-failure) that exit normally. Card 9 adds an exec-branch test: run `run.sh` with no `PROWLER_BUILD_ONLY` and no args (child prints Usage, exits 1) and assert `.build.lock` is absent afterward — the harness previously only ever set `PROWLER_BUILD_ONLY=1` and never exercised the exec branch.
- **[BLOCKING] "chromedp fallback has no render/network-idle wait before capturing HTML"** — `chromedp.Navigate` returns at the `load` event, before JS-driven content renders, defeating the browser fallback's whole purpose. Card 7 now specifies a render-settle step before `OuterHTML`: `chromedp.WaitReady("body", chromedp.ByQuery)` then `chromedp.Sleep(~2s)`, documented as a deliberate parity substitute for weblens/Puppeteer's `networkidle0` (chromedp has no built-in network-idle action).
- **[NIT] "Lock timeout silently diverges from discussion.md's ~120s to the plan's ~300s"** — added an overview Shared Decision "build-lock timeout ~300s (overrides discussion.md's ~120s)" recording the change and its rationale (staleness reclaim must sit above a legitimate cold build incl. ~4× Windows AV overhead; owner-token + atomic-rename make the larger window harmless), matching the treatment given to the layout override.
