Added a new Decision, "All-or-nothing output: the listing is buffered until the walk succeeds" — nothing reaches stdout until the walk completes, so "emits nothing on stdout, exits non-zero" holds literally at any depth. Added a harness assertion that pins it — the mid-walk-failure fixture fails *after* the root blobs and one complete subtree are collected, so a streaming implementation passes every other test and fails only this one.

The rule is otherwise unchanged at every depth — only the addressing differs.
- `20260829-104446-discussion-review-r4.md` — "URL-encoding reject set narrower than the stated support envelope": the parenthetical blacklist is replaced by an explicit whitelist, `^[A-Za-z0-9._/-]+$`, applied after slash-stripping and before any `gh` call. Stated why a whitelist rather than a blacklist: it makes the accepted set exactly the envelope that was verified, where an illustrative blacklist would silently admit untested non-ASCII paths.
