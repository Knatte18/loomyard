## Findings

### [BLOCKING:design] Re-run after a live-strand refusal skips readiness
**Location:** Batch 2 / Card 3 (step-6 llm block, `Long` text, `--no-attach` usage). **Issue:** Under the new signal, the main refusal path is the startup window closing on a LIVE pane (for example an unrecognized gate or a slow boot), and the strand is left in place. On the next `start`, `resolveDriverStrandAction` (`internal/loomcli/bootstrap.go`) answers `driverStrandLive`, so `mustSpawnDriver` returns false and `runDriverSpawnAndWait` skips step 6 and returns true with the driver still parked. The kept discussion rationale ("the next `start` already handles a dead strand as a corpse") covers only the dead case. The plan's new `--no-attach` wording ("returns once the driver is confirmed up") is false for that re-run. **Fix:** Card 3 should state how a later `start` treats a live-but-never-ready strand. Either it re-awaits readiness or refuses, or the residual is stated explicitly in the step-6 comment and in the `Long`/`--no-attach` text.

### [NIT:consistency] run.go header leaves AwaitStarted out of the Run surface
**Location:** Batch 1 / Card 1 (`internal/shuttleengine/run.go`). **Issue:** Card 1 updates `wait.go`'s header to name `AwaitStarted`. It also forbids any other `run.go` change, which leaves stale two sentences that describe the handle's public surface as Wait plus Interrupt/Send. These are the file header's "Wait (wait.go) and Interrupt/Send round out the Run handle's public surface" and the `Run` type doc. **Fix:** Add `AwaitStarted` to the `run.go` header sentence and the `Run` type doc, or state why they stay as they are.
