## Findings

### [BLOCKING:design] Cleanup's clean-state cell never asserts "primary weft branch intact"
**Location:** `internal/fabricengine/fabrictest/verbs.go:723-764` (`cleanupCase`)
**Issue:** Card 16 (batch 6) explicitly specifies `Topology.Cleanup`'s clean-state effect as "orphan managed branches gone, **primary weft branch intact**." The delivered `cleanupCase().Expect(...).Effect` closure checks only that the orphan branch is gone (`branchExists(h.PairWeftSibling(f.Slug), orphan)`); it never checks the primary weft branch (e.g. `main-weft`) survives. This is exactly the R3 defect class the harness exists to catch, and `doc.go`'s own sabotage-proof row (4) admits the gap directly: "fabrictest's own clean/Cleanup/'.' cell exercises Cleanup's ordinary orphan-deletion path... but does not itself move the prime warp worktree off its default branch, so it does not independently exercise this defence" — falling back to the pre-existing hermetic test `TestCleanup_PrimaryBranchSurvivesForceWhenNotCheckedOut` instead of the harness's own cell. A future regression in `primaryWeftBranch`'s carve-out is therefore not caught by this harness at all, silently defeating part of the deliverable's stated purpose.
**Fix:** Add an `Arrange` variant (or a second verb case) that checks out the prime warp worktree onto a non-default branch before running `Cleanup`, and assert the primary weft branch still exists afterward — matching card 16's stated clean-state effect and making the sabotage proof for row (4) independently provable inside `fabrictest` rather than routed through a different package's pre-existing test.

### [NIT:consistency] Stale line-number citations in verbs.go doc comments
**Location:** `internal/fabricengine/fabrictest/verbs.go:94` (`add.go:286-308`), `verbs.go` Omissions table (`cleanup.go:275`)
**Issue:** `rollbackAdd`'s branch-delete step is at `add.go:287-308`, and `cleanup.go`'s `deleteBranch` call is at line 283, not 275 — both off by several lines from the cited references (the underlying technical claims themselves check out on inspection).
**Fix:** Re-verify and correct the cited line numbers against the current `add.go`/`cleanup.go` the next time either file is touched.

### [NIT:design] `KindEitherProceedsOrRefusedBefore` has no explicit content-survival check
**Location:** `internal/fabricengine/fabrictest/matrix_test.go:142-182` (`assertPlantedContentSurvives`), `verbs.go` `checkoutCase`'s `dirtyWarpTracked` branch
**Issue:** `runCell` only calls `assertPlantedContentSurvives` when `exp.Kind == KindProceeds`; the one `KindEitherProceedsOrRefusedBefore` cell (`dirtyWarpTracked × Checkout`) relies solely on its own `Effect` (which checks half-switch only) plus the generic `AssertNoUnpermittedChange` to implicitly catch a discarded tracked modification. This is very likely functionally equivalent (a discarded modification would surface as an unpermitted content change with no declared permit root), but the doc comment's promise — "the cell asserts what must hold either way — the tracked modification is still on disk" — is not an explicit, named assertion the way every other kind gets.
**Fix:** Either extend `assertPlantedContentSurvives`'s dispatch to also run for `KindEitherProceedsOrRefusedBefore`, or add an explicit content-hash check to `checkoutCase`'s `dirtyWarpTracked` `Effect` so the guarantee is a named assertion rather than an implication of the manifest diff.

Cleanup's clean-state cell doesn't assert primary-weft-branch survival per card 16; the harness silently can't self-prove its own row-4 sabotage claim.
