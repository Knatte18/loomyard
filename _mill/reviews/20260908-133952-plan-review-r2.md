## Findings

### [NIT:consistency] Card 3 doc contradicts card 6's wireHub

**Demoted-from:** BLOCKING
**Location:** batch 1 card 3 (`PlanRules.DefaultPlanDir`) vs batch 2 card 6 (`wireHub`)
**Issue:** Card 3 requires the field's doc comment to state "`wireHub` calls the same field with the hub anchor path" (mirroring discussion.md:116), but card 6 has `wireHub` call `cliwire.ResolvePlanDir(planDir, geom.PlanDir)` and never touch `wireModule.Plan.DefaultPlanDir` — so the prescribed comment is false the moment card 6 lands.
**Fix:** Pick one: either have card 6's `wireHub` call `wireModule.Plan.DefaultPlanDir(anchorPath)` as the second argument, or drop the `wireHub` clause from card 3's required doc text.

### [BLOCKING:scope] Card 5 cannot source webster's missing-plan message

**Location:** batch 1 card 5 (`websterFixture`)
**Issue:** The fixture's `MissingPlanRefusal` must "reproduce webster's live message", but that string lives only at `internal/webstercli/wiring.go:243`, which is in neither card 5's `Context:` nor `Edits:`; card 3 quotes the hub refusal verbatim but never this one, and `internal/logger/sink.go` is likewise absent while the card requires `logger.SetDurableSinkDir`/`logger.Info` assertions.
**Fix:** Add `internal/webstercli/wiring.go` and `internal/logger/sink.go` to card 5's `Context:`, or inline the refusal text in the card the way card 3 inlines the hub refusal.

### [BLOCKING:scope] Stencils seed-failure error path has no test

**Location:** batch 1 card 5 (Stencils bullet)
**Issue:** discussion.md:374 names "a seed failure on the default is a hard error naming the directory" as a cliwire test candidate; card 5's stencils bullet covers only the seeded default, the untouched override and the returned path, leaving `ResolveStandalone` step 5's only error return (`"%s: seed the standalone stencils directory %s: %w"`) unexercised in the one package that now owns it.
**Fix:** Add a case that makes the derived stencils path uncreatable (e.g. a regular file at `<stateDir>/_lyx`) and asserts the error names `m.Name` and the directory.

### [NIT:consistency] Card 4 states error handling for step 1 only

**Location:** batch 1 card 4 (`ResolveStandalone` steps 2–3)
**Issue:** Step 1 says "return the zero `Standalone` and the error on failure"; steps 2 (`standalonestate.Derive`) and 3 (`refuseNestedStandaloneGeometry`) are written as bare calls with no stated disposition of their errors, even though both are fallible and both must abort the prologue.
**Fix:** State the same return-on-error rule for steps 2 and 3.

### [NIT:scope] Card 7 omits burler's runner construction lines

**Location:** batch 2 card 7 (`wireStandalone`)
**Issue:** The card enumerates `reedGeom`, the three config loads, `burlerengine.New` and the field assignments, but never names `reedengine.New(reedCfg, reedGeom)` or `shuttleengine.NewDetachedRunner(...)`, which the `runner` argument it does name depends on.
**Fix:** Say explicitly that both survive unchanged, reading `res.StateDir`/`res.Target` where they read the old locals.
