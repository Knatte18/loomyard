## Findings

### [BLOCKING:scope] loom.md's 4-step bootstrap diagram is never updated
**Location:** batch 2, Card 10 (also relevant: batch 5 Card 23, batch 7 Card 33)
**Issue:** `manifest/designs/loom.md`'s "Entry point — the session bootstrap" section pins an ASCII `lyx loom run:` diagram with exactly four steps (tmux up, add strand, spawn driver, attach) and no mention of seeding, committing, or the parent-branch record. Card 23 inserts three real pre-steps (resolve/write provenance, `loomshed.Seed`, `CommitWeftPaths`) ahead of those four. Card 10 edits this same file but only touches the "The run-launcher." paragraph — no card updates the diagram itself, so the shipped `run` verb's actual step sequence will contradict the pinned design doc.
**Fix:** Add a requirement (Card 10 or a new card in batch 5/7) to rewrite the `lyx loom run:` diagram to include the seed/commit/provenance steps ahead of the four listed ones.

### [BLOCKING:scope] loom-status-spec.md line 9 misattributes Shed.Run to the wrong verb
**Location:** batch 5, Card 25
**Issue:** `contracts/specs/loom-status-spec.md` (line 9) currently reads "`lyx loom run` (via `Shed.Run`) rewrites the shell on every step." Per Card 17/23's design, `Shed.Run` is invoked by the separate `drive` verb (run in a detached child spawned by `run`), never by `run` itself — `run` only ensures the driver exists and attaches. Card 25's enumerated edits (worked-example intro sentence, seed-section role sentence, single-writer parenthetical) don't include this sentence, so it becomes a false statement about which command owns the phase-machine loop once this ships.
**Fix:** Add this sentence to Card 25's list of corrections — attribute the "rewrites the shell on every step" behavior to the `drive` verb, not `run`.

### [NIT:consistency] batch 4's depends-on [1, 3] is not reflected by any of its cards
**Demoted-from:** BLOCKING
**Location:** `00-overview.md` Batch Index; batch 4 (loomcli-core)
**Issue:** Batch 4 declares `depends-on: [1, 3]`, but none of Cards 15–20's Context/Edits/Creates reference batch 1's new files (`origin.go`, `commitweftpaths.go`) or batch 3's new accessors (`LoomDriverLog`, `LoomBootstrapLock`, `ErrSeedExists`) — Card 16's `loomshed.Deps` wiring uses only the pre-existing `LoomStatusFile`/`LoomRunLock`/`LoomStatusLock` accessors, whose signatures Card 11 leaves byte-identical. Every other batch's Scope prose explicitly justifies its cross-batch dependencies (e.g. batch 6: "It depends on batch 2 for... and on batch 5 for..."); batch 4's Scope gives no such rationale for [1, 3], and no card substantiates it.
**Fix:** Either drop batch 4's dependency on 1 (and on 3, if truly unneeded) so it can run in parallel, or add a sentence to batch 4's Scope naming the specific reason it needs those batches first.
