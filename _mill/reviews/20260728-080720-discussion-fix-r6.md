## Fixed

- `20260728-080652-discussion-review-r6.md` — "[NOTE] Cache file schema left implicit": pinned the `credentials.json` schema to two fields, `token` (string) and `resolved_at` (RFC 3339 UTC), with freshness computed as `now - resolved_at < 12h` and no stored expiry, so a TTL change never requires migrating existing cache files. Any other shape is a cache miss under the existing corrupt-cache rule. Recorded in the `token-resolution-and-cache` Decision.
- `20260728-080652-discussion-review-r6.md` — "[NOTE] 401 replay with an env-var token re-resolves to the same value": chose the skip-replay option and stated why. When the token came from `GH_TOKEN`/`GITHUB_TOKEN`, a 401 returns immediately instead of invalidating and replaying — environment variables outrank the cache by rule, so re-resolution is guaranteed to yield the identical value and the replay is a guaranteed-identical second failure. The returned error names the environment variable as the rejected source, which is actionable where a silent retry is not. Invalidate-and-replay now applies only to cache-sourced or freshly-`gh`-resolved tokens. Recorded in the `token-resolution-and-cache` Decision.
