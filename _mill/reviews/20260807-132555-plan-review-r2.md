## Findings

### [BLOCKING] Card 9's scratchDir-resolution placement contradicts its own use sites
**Location:** batch 02, card 9 (`internal/treadleengine/run.go`)
**Issue:** The card says to resolve `scratchDir` (falling back to `runDir`) "inside the existing 'Seam defaulting happens here, once, at Run's entry' block" — which in the current source sits at line ~120, defaulting only `pause`/`runCommand`, well *after* the deferred `clearPauseFlag` closure (line 73), `os.MkdirAll(runDir,...)` (line 89), `lock.TryAcquireWriteLock` (line 98) and the entry-time `clearPauseFlag` call (line 111). The same card also requires `scratchDir` to be used at every one of those earlier sites (the deferred clear, the lock path, the entry-time clear) and requires `os.MkdirAll(scratchDir,...)` placed "right after the existing `os.MkdirAll(runDir,...)`" — i.e. before the seam-defaulting block even runs. Following the card literally either produces a forward-reference compile error (the top-of-function `defer func(){...}` closure would reference a `scratchDir` local not yet declared in source order) or silently requires hoisting the whole seam-defaulting block far earlier in `Run`, which the card never states.
**Fix:** Rewrite card 9 to explicitly resolve `scratchDir` at the very top of `Run` (before the deferred-clear closure), independent of where `pause`/`runCommand` get defaulted, and drop the "inside the Seam defaulting block" phrasing, or explicitly instruct relocating that block's opening lines earlier and say so.

### [NIT] Card 28's "nine sites" count is off by one
**Location:** batch 04, card 28 (`internal/reedengine`)
**Issue:** The card states reed repeats the `WorktreePath()+dotLyxDirName` join "at nine sites," but its own per-file enumeration (lifecycle.go: 2 SaveState + 1 reedStateFileName join + 1 LoadState = 4; lock.go: 1; spawn.go: 2; strand.go: 3) sums to 10, matching the actual production call sites (verified by grep: lifecycle.go:545,676,778,961; lock.go:66; spawn.go:143,183; strand.go:309,348,471).
**Fix:** Correct "nine" to "ten" in both places the card states the count; the enumerated per-file list itself is already accurate and complete.

### [NIT] Shared decision overclaims post-batch-1 literal exclusivity
**Location:** batch 01, card 2 / Shared Decision `lyxdirs-is-the-only-declarer`
**Issue:** `internal/configengine/config.go`'s `FindBaseDir` contains the error string `"not initialized: _lyx/ directory not found"`, a substring occurrence of `_lyx` that card 2 never touches (it only removes the `LyxDirName` const and retargets `filepath.Join` call sites). The shared decision's claim that after batch 1 the literal `"_lyx"` "exist[s] in exactly one production file" is therefore not literally true, even though the machine-enforced guard (which only checks `filepath.Join`/`+`/const-decl contexts) correctly still passes.
**Fix:** Either have card 2 also reword that error string to reference `lyxdirs.LyxDirName`, or soften the shared decision's wording to scope the claim to path-construction contexts (matching what `TestEnforcement_GeometryLiterals` actually polices).
