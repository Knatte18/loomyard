## Findings

### [NIT] go-git ignores GIT_CONFIG_GLOBAL for commit identity
**Location:** Batch 3 (write-surface) / Card 8
**Issue:** The card states "because TestMain runs under `lyxtest.HermeticGitEnv()` the neutral `user.name`/`user.email` are available; read them via go-git config or set an explicit signature." `HermeticGitEnv` only sets identity via `GIT_CONFIG_GLOBAL`/`GIT_CONFIG_NOSYSTEM` (hermetic.go), which go-git v5 does not honor — its global scope resolves from `$HOME`/XDG, so "read them via go-git config" yields no identity or leaks the operator's real `~/.gitconfig` (non-hermetic).
**Fix:** Drop the "read via go-git config" option; require the poc to pass an explicit `object.Signature` on `Worktree.Commit`.

## Verdict

APPROVE
Well-formed, decision- and constraint-aligned; one non-blocking identity-source caveat.
