## Findings

### [NIT:design] AttachArgv does not floor rows-reserved before planning
**Location:** `internal/reedengine/attach.go:123`
**Issue:** `render.Box{... H: rows - reserved}` has no lower bound; a numeric `#{status}` readback (e.g. a multi-line status bar) large enough relative to `rows` yields a non-positive box height passed straight into `planLayout`/`render.Rules`. `render.Rules`'s own clamp machinery prevents a crash and floors every cell at 1, but the interaction is untested and undocumented as a deliberate degrade.
**Fix:** Either clamp `reserved` so it never exceeds `rows-1` before subtracting, or add a one-line doc/test note that an oversized `#{status}` reservation is accepted and handled by `render.Rules`'s existing floor.
