## Fixed

- `20260811-155416-plan-review-r3.md` — "[BLOCKING:design] Omission direction fires on ancestor create/prune".
  Verified: `createPortal`'s own doc comment states `fslink.CreateDirLink` `MkdirAll`s `filepath.Dir(link)` and creates the mirrored `_portals/<RelPath>/` chain, `writeLaunchers` `MkdirAll`s its slug directory, and both `removePortal` and `removeLaunchers` call `pruneEmptyAncestors`.
  Card 29's coverage rule now extends **upward** as well as downward: an entry additionally covers every ancestor directory of its `Target` up to but excluding the hub root, and only for a diff change whose entry is `KindDir`.
  The `KindDir` restriction is what keeps it honest — a file or link appearing beside a recorded target is still uncovered.
  `Change` already carries `Before`/`After` `Entry` values with a `Kind` field, so no manifest API changes.
  Stated in the covering-root Shared Decision too, citing the harness's own `filepath.Dir(portal)`/`filepath.Dir(launcher)` permitted roots as the existing concession to the same shape.
- `20260811-155416-plan-review-r3.md` — "[BLOCKING:design] `removeLink` records an already-absent link".
  Verified: `fslink.Remove` returns nil for an absent link by design, and `checkPathRequest` passes an absent target through as a no-op success before any check runs, naming the idempotent callers that depend on it.
  Card 12 now requires an `os.Lstat` probe before `fslink.Remove` — `Lstat` not `Stat`, so a dangling link still counts as present — recording only when the probe found something and the removal then succeeded.
  Card 16 gains the absent-target and present-link cases.
- `20260811-155416-plan-review-r3.md` — "[BLOCKING:design] The `"."` exemption leaves the reset teardown uncovered".
  Verified, including that `hubPath` is derived immediately before both `resetHub` calls.
  Two changes: card 29's `"."` exemption is now one-directional and split by kind — always exempt from commission (no `"."` key can ever exist in a manifest), exempt from omission only for the constructive `dir_created` case, and **counted** for `path_removed`, where nothing survives the teardown for a finer entry to name;
  and card 14 no longer hedges about a nil recorder at `resetHub`, requiring the `rec = NewMutations(hubPath)` assignment to be moved directly after each `hubPath = HubPath(cwd, name)` line.
- `20260811-155416-plan-review-r3.md` — "[BLOCKING:scope] `ReconcileAll` writes N config files, not one".
  Verified: it returns `[]Result`, one per registered module, each carrying `Applied bool`.
  Card 25 now requires one `KindFileWritten` per `Result` whose `Applied` is true, targeted at `configengine.ConfigFile(baseDir, r.Module)`, and notes `ReconcileFabricAt` returns a single `Result` under the same condition.
  `internal/fabriccli/cli_test.go` already imports `configengine` and uses that helper, so the import is established in the package.
