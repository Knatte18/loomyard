## Findings

### [BLOCKING:scope] Card 5's Context omits the Engine/Geometry definitions it requires
**Location:** Batch 1 / Card 5 **Issue:** Requirements ask for a test "against a hand-built Engine with a known Geometry.AnchorPath," but neither `internal/reedengine/lock.go` (`Engine`, `New`) nor `internal/reedengine/geometry.go` (`Geometry`) is in Card 5's Context, and no sibling fixture file (e.g. `lock_test.go`'s existing `newTestEngine`, itself also absent from Context) is pointed at either — unlike Cards 13/18, which reuse an already-Context'd test file's pattern for the same "hand-built Engine" ask. **Fix:** Add `internal/reedengine/lock.go` and `internal/reedengine/geometry.go` (or point at `lock_test.go`'s `newTestEngine`) to Card 5's Context.

### [NIT:consistency] header_test.go's new tests never restore logger.SetOutput
**Demoted-from:** BLOCKING
**Location:** Batch 4 / Card 20 **Issue:** Card 19 makes the blocking tail call `logger.SetOutput(io.Discard)`; Card 20's new tests exercise that path via `cmd.Execute()`, and its Requirements restore `headerWatch`/`headerPark` via `t.Cleanup` but say nothing about the logger sink. Every other `logger.SetOutput` call site in this repo (`internal/mergeresolve`, `internal/loomshed`, `internal/stencilcli`, `internal/landingshed`, `internal/selfreportengine`, `internal/treadleengine`, `internal/shuttleengine`, `internal/shedadapters` ×2, `internal/websterengine`, `internal/fabricengine`, `internal/stencilstore`) pairs it with `t.Cleanup(func() { logger.SetOutput(os.Stderr) })`; this card would leave the discarding sink live for the rest of the `internal/reedcli` test binary. **Fix:** Add a `t.Cleanup(func() { logger.SetOutput(os.Stderr) })` requirement to every new test in Card 20 that drives the blocking path.

### [NIT:consistency] template.go's "exactly four keys" comment goes stale
**Location:** Batch 1 / Card 3 **Issue:** `internal/reedengine/template.go`'s `ConfigTemplate` godoc states "Exactly four keys use the `${env:VAR:-default}` syntax" (tmux, shell, debug_log, mouse); adding `watchdog` in the same shape makes this five, and no card in Batch 1 edits `template.go`. **Fix:** Add `internal/reedengine/template.go` to Card 3's Edits and update the count/enumeration.

### [NIT:consistency] ensureServerAndSessionLocked's docstring omits watchdog
**Location:** Batch 2 / Card 11 **Issue:** `lifecycle.go`'s `ensureServerAndSessionLocked` doc comment says it "validates capability, debug_log, mouse, and header template before any tmux round trip"; Card 11 inserts a watchdog check into that same pre-tmux block but only asks for a local preceding comment, not an update to this function-level enumeration. **Fix:** Add one line to Card 11 updating the function's top comment to also name `watchdog`.

### [NIT:design] liveBoxLocked becomes production-dead code within this same batch
**Location:** Batch 2 / Cards 6–7 **Issue:** Card 6 keeps `liveBoxLocked()` as a delegating wrapper "so no existing caller changes," but Card 7 (same batch) rewrites its only production caller (`applyLayoutLocked`) to go through `applyLayoutLockedOpts`/`liveBoxLockedOK()` directly, so after Batch 2 lands, `liveBoxLocked()` has zero production callers and exists only for its own regression test (`windowsize_test.go`). **Fix:** Either note explicitly that the wrapper becomes test-only after Card 7, or fold its removal into Card 7 instead of preserving it.
