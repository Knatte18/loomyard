## Problem

`test-suite-overhaul` (#022) fixed two individual tests that blocked on real production timeouts for no substrate reason (`internal/githubclient`, `internal/webstercli`). Re-measuring after that fix surfaced two follow-on problems the original task didn't cover: `internal/scoutengine` is now the single largest cost in both Tier 1 (~1.9s of ~3.86s) and Tier 2 (~3.9s of ~6.48s) on the Linux baseline, and `internal/webstercli`'s presence in the `integration` build tag looked — on a first pass — accidental rather than substrate-driven. The deeper problem underneath both: the Tier 1/Tier 2 split is documented informally ("Tier 2 = real git/tmux/filesystem/cross-compile") but nothing enforces that definition beyond `cmd/lyx/tierpurity_test.go`'s narrow untagged-tests-spawn-nothing guard, so a test can end up `-tags integration` purely for being slow rather than for touching real substrate — exactly the githubclient/webstercli shape, and (per this discussion's own findings below) not actually the scoutengine or webstercli shape after all.

**This discussion's exploration overturned one of the task's own starting premises.** `internal/webstercli/verbs_test.go`'s shared fixture (`newVerbsFixture` → `newScratchRepo`, `internal/webstercli/verbs_test.go:206`) runs a real `git init`/`git config`/commit via `gitexec.RunGit` for every test in the file. The original brief's claim that this file is "fully hermetic" is true only for tmux/Claude (both are faked) — not for git. Per the substrate rule this task exists to formalize, real `git init` is squarely Tier-2 substrate, and moving the file to untagged would hard-fail `cmd/lyx/tierpurity_test.go`'s existing ban on `gitexec.RunGit` in untagged files. **`verbs_test.go` is correctly tagged today.** See Decisions below for how this reshapes scope.

A second premise needed correcting too: the brief frames scoutengine's cost as "real LSP-server-startup tests," but the specific files driving the Tier 1/Tier 2 cost (`daemonstate_test.go`, `supervised_test.go`'s two retry-exhaustion subtests, `refs_test.go`) never spawn a real language server — they spawn a generic `sleep`/`true` process purely as a PID-liveness fixture (already allowlisted in `tierpurity_test.go`'s `allowedSpawners`) and exercise retry/lock/timeout decision logic with an already-short, caller-supplied timeout (300ms, passed as a function argument, not a hardcoded const). Only the four `*_integration_test.go` files (plus one oddly-skip-gated subtest in `supervised_test.go`) actually require `gopls`/`pyright`/`csharp-ls` on `$PATH`.

## Scope

**In:**
- New `scout` build tag, scoped narrowly to tests that require a real external LSP binary: `ensureserver_integration_test.go`, `refs_integration_test.go`, `supervised_integration_test.go`, `toolchain_integration_test.go` (retagged from `integration` to `scout`, removing them from Tier 2), plus splitting `supervised_test.go`'s `TestEnsureSupervised_StaleSocketCleanupAvoidsEADDRINUSE`-shaped subtest (the one skip-gated on `exec.LookPath("gopls")` via `t.Skip` rather than a build tag — inconsistent with its siblings) into its own `scout`-tagged file for consistency.
- `daemonstate_test.go`, the rest of `supervised_test.go`, `refs_test.go`, `ensureserver_test.go`, `definition_test.go`, `lspclient_test.go` stay untagged, unchanged — they are substrate-free decision-logic tests, the same category as `internal/buildercli`'s already-accepted `TestPollCmd_*` real-time-bounded tests.
- Generalizing `cmd/lyx/tierpurity_test.go`'s `isTierTagged()` to recognize a known-tags list (`integration`, `smoke`, `scout`) instead of hardcoding `integration`/`smoke`, so a `scout`-tagged file is correctly exempted from the untagged-purity scan rather than accidentally passing only because its tokens happen to already be on `allowedSpawners`.
- Documenting `go test -tags scout ./...` in `docs/benchmarks/running-tests.md` as a manual, explicitly-invoked command — no CI wiring (there is no CI in this repo at all: no `.github/workflows`, no other CI config found anywhere in the tree).
- Auditing `internal/webstercli`'s previously-unchecked `smoke_test.go` and confirming `internal/websterengine`'s six `integration`-tagged files (`beginbatch_test.go`, `gitwrap_test.go`, `integration_test.go`, `recordbatch_test.go`, `recoverbatch_test.go`, `runlevel_test.go`) are correctly tiered — already confirmed during this discussion by reading each file's doc comment: all six back `WorktreeRoot` with a real scratch git repo (`gitwrap_test.go`, `runlevel_test.go`, `recoverbatch_test.go`, `recordbatch_test.go`, `beginbatch_test.go`, `integration_test.go` all state this explicitly). No re-tiering expected here; the plan should still touch each file briefly to record the confirmation, not just take this discussion's word for it.
- Writing the explicit substrate rule into `docs/benchmarks/running-tests.md`'s "## The two tiers" section (primary), with a one-line pointer added under CONSTRAINTS.md's existing Test Tier Purity Invariant section (CONSTRAINTS.md is the authoritative invariant index every session reads first).
- A narrow mechanical guard extension: flag any untagged `*_test.go` file containing a literal `time.Sleep(...)` call whose duration argument is a compile-time constant ≥ 1 second, using the same `allowedSpawners`-shaped allowlist for legitimate exceptions. This is additive, not retroactive — it would not have caught the historic `githubclient`/`webstercli` bugs (those were a production-side `const` timeout a test couldn't override, not a test-side `Sleep` call); it's a new, narrower net for future regressions of the literal-Sleep shape. Deliberately excludes `context.WithTimeout` ceilings (a ceiling doesn't guarantee blocking — `refs_test.go`'s 5s contexts fail fast via `exec.LookPath`, never actually waiting 5s) and short bounded-retry constants like `supervised_test.go`'s 300ms timeout, to keep false positives low.
- A full sweep of every `//go:build integration` file repo-wide (85 files found across `cmd/lyx`, `internal/boardcli`, `internal/boardengine`, `internal/buildercli`, `internal/builderengine`, `internal/configcli`, `internal/fabriccli`, `internal/fabricengine`, `internal/gitexec`, `internal/gitrepo`, `internal/hubgeometry`, `internal/idecli`, `internal/ideengine`, `internal/initcli`, `internal/initengine`, `internal/loomengine`, `internal/lyxtest`, `internal/perchcli`, `internal/reedcli`, `internal/reedengine`, `internal/scoutengine`, `internal/treadleengine`, `internal/webstercli`, `internal/websterengine`, `plugins/prowler` — full list captured in this session's exploration, not re-pasted here since it is mechanically reproducible via `grep -rl "^//go:build integration" --include="*_test.go" .`), checked against the newly-written substrate rule. Any confirmed mis-tiering (hermetic-but-tagged, or slow-for-no-substrate-reason) gets fixed in this same task — **the user explicitly chose the full fix-everything variant over an audit-only pass, accepting the open-ended time cost this implies.** Packages whose entire subject is git/git-like substrate (`fabricengine`, `gitrepo`, `gitexec`, `hubgeometry`) are near-certain to be correctly tagged and are the lowest-value targets for close reading; CLI-wrapper packages riding along an engine package's tag are the highest-value targets, mirroring the mis-tiering shape already found once (webstercli riding websterengine's premise, though it turned out correct) and once for real (the original githubclient/webstercli timing bugs).

**Out:**
- No refactor of `verbs_test.go` to avoid real git — the premise that it needed to move was wrong; there is nothing to fix there.
- No CI scaffolding of any kind (no `.github/workflows` file, no path-filtered job) — there is no CI in this repo today and adding the first one is out of proportion to this task.
- No broader mechanical guard for "any ≥1s time.Duration literal passed to any function" (would also flag legitimate context deadlines) — only the literal-`time.Sleep` shape, per Decisions below.
- No real-LLM-call testing of any kind, confirmed already out of scope: `go test` never calls a real LLM API today (checked via grep for API-key/anthropic-endpoint patterns); that boundary belongs to Sandbox/Crucible, not `go test`. This task does not change that boundary, only documents it as an explicit non-goal in the new substrate-rule writeup.

## Decisions

### webstercli is correctly tagged, not mis-tiered

- Decision: Treat `internal/webstercli/verbs_test.go` as correctly `-tags integration` today. No re-tiering, no fixture refactor.
- Rationale: `newVerbsFixture` → `newScratchRepo` (`verbs_test.go:47-56, 206`) runs real `git init`/`git config` via `gitexec.RunGit`, used by every test in the file (`TestBeginBatchCmd_HappyPath`, `TestAwaitBatchCmd_ReportPresenceEnvelope`, `TestRecordBatchCmd_Envelope`, `TestRecoverBatchCmd_RunningThenTerminal`, `TestRunCmd_ErrRunBusySkipsWeftBackstop`, `TestPersistentPreRunE_*`). Real git spawn is Tier-2 substrate by the rule this task writes down. `cmd/lyx/tierpurity_test.go` already bans `gitexec.RunGit` in untagged files — moving this file to untagged would fail that guard outright.
- Rejected: (a) refactoring the fixture to avoid a real git repo — rejected because the production code under test (`headSHA`/`dirty`/drift computation) plausibly needs a real repo to test meaningfully, and this was judged not worth the risk/cost of touching a shared fixture used by 8 tests; (b) dropping webstercli from scope entirely — rejected in favor of still auditing `smoke_test.go` (unchecked) and confirming `websterengine`'s integration files, since the original brief's "confirm the rest are equally hermetic" ask is still worth doing even though the answer for `verbs_test.go` itself flipped.

### `scout` tag scoped to real-external-binary tests only

- Decision: Only the 4 existing `*_integration_test.go` scoutengine files (retagged `integration` → `scout`) plus one currently-inconsistent subtest (split out to its own `scout` file) move behind the new tag. The untagged decision-logic tests (`daemonstate_test.go`, most of `supervised_test.go`, `refs_test.go`, `ensureserver_test.go`, `definition_test.go`, `lspclient_test.go`) stay exactly where they are.
- Rationale: These files don't need `gopls` at all — they test internal retry/lock/state-file logic with an already-bounded, already-parameterized timeout (300ms passed as an argument, not a hardcoded const) and a generic held subprocess (`sleep 5`/`true`) as a PID-liveness fixture only, already permitted by `tierpurity_test.go`'s existing `allowedSpawners` entries for these two files. Moving them behind `scout` anyway would remove real, useful coverage of that logic from every default run (neither `go test ./...` nor `-tags integration ./...` would ever exercise it) for a modest wall-clock saving, and would contradict this same task's item on writing down "never just slow" as the substrate rule.
- Rejected: (a) moving the whole package behind `scout` regardless of individual substrate ("scoutengine is special because its subject is LSP supervision") — considered and rejected after direct code inspection showed the specific cost driver doesn't touch a real LSP binary; (b) var-seaming the 300ms/context timeouts further instead of tagging anything — rejected because the four genuinely gopls-dependent files can't be var-seamed away (they need the real binary, full stop), so a tag is still required for those; the decision-logic files don't need seaming further since their timeout is already a caller-supplied 300ms, not a hardcoded multi-second const.

### `scout` tag: manual invocation only, no CI

- Decision: Document `go test -tags scout ./...` in `docs/benchmarks/running-tests.md` as a manual command, explicitly stating scout tests are hidden behind their own tag and why. No CI workflow of any kind is added.
- Rationale: No CI exists anywhere in this repo (`.github/workflows` absent; no other CI config found). Wiring a path-filtered job would mean introducing the repo's first CI config as a side effect of this task — out of proportion.
- Rejected: scaffolding a minimal `.github/workflows` job now — rejected as scope creep; revisit if/when CI is ever added to the repo for other reasons.

### `isTierTagged()` generalized to a known-tags list

- Decision: Update `cmd/lyx/tierpurity_test.go`'s `isTierTagged()` to check the `//go:build` line against a small list of known opt-in tags (`integration`, `smoke`, `scout`) instead of two hardcoded `strings.Contains` checks.
- Rationale: Without this, a file tagged `//go:build scout` is treated as "untagged" by the guard's own bookkeeping and scanned for banned tokens — currently harmless only because the specific files being retagged already have file-level `allowedSpawners` entries covering their tokens, but a latent false-positive-failure trap for any future `scout`-tagged file whose tokens aren't already allowlisted.
- Rejected: leaving it as-is and relying on the existing allowlist — rejected, since the fix is small and removes a real (if currently dormant) footgun.

### Narrow real-time-wait guard: literal `time.Sleep` only

- Decision: Extend the tier-purity guard machinery to flag any untagged `*_test.go` file containing a literal `time.Sleep(...)` call whose duration argument is a compile-time constant ≥ 1 second, allowlisted the same way `allowedSpawners` works today.
- Rationale: Low false-positive risk — doesn't touch `context.WithTimeout` ceilings (a deadline that may never be reached, e.g. `refs_test.go`'s 5s contexts that fail fast via `exec.LookPath` and never actually wait 5s) or short, intentionally-bounded retry constants (`supervised_test.go`'s 300ms, passed as an explicit function argument with a comment justifying the value). This is an additive net for future regressions of the "test blocks on a literal multi-second sleep" shape specifically, not a retroactive fix — it would not have caught the historic `githubclient`/`webstercli` bugs, both of which were production-side hardcoded `const` timeouts a test couldn't override, not a test-side `Sleep` call. That distinction should be stated plainly in the guard's own doc comment so a future reader doesn't assume it's more general than it is.
- Rejected: a broader check flagging any ≥1s `time.Duration` literal passed to any function — rejected as too blunt; it would flag legitimate context-deadline literals throughout the suite and require a much larger allowlist built on judgment calls rather than a clear mechanical signal.

### Substrate rule lives in running-tests.md, pointed to from CONSTRAINTS.md

- Decision: Write the full substrate definition — real git subprocess spawning, real filesystem junctions/symlinks, real `tmux` sessions, real cross-compilation, real external-binary spawn (the new category this task's scoutengine finding surfaces) — into `docs/benchmarks/running-tests.md`'s existing "## The two tiers" section. Add one line under CONSTRAINTS.md's Test Tier Purity Invariant pointing to it.
- Rationale: `running-tests.md` already explains the tier concept in prose; that's where a reader goes first. CONSTRAINTS.md is the authoritative invariant index every session must read per this repo's own CLAUDE.md — a pointer keeps it discoverable without duplicating the full explanation into the terse invariant-index format.
- Rejected: writing the full rule only into CONSTRAINTS.md — rejected since CONSTRAINTS.md's own stated purpose is a terse index ("fuller design/how-to lives in godoc and docs/, not here").
