## Batch Scope

This batch delivers item 5: it flips `ensureServer`'s single live dispatch arm from `ensureNative` to `ensureSupervised` for Go, carries the shared 10-minute idle timeout onto the supervised daemon, keeps `ensureNative` as an in-function fallback, and closes the now-live wedged-daemon staleness gap with a bounded re-dial-under-lock-then-one-restart escalation using `proc.KillPID`. It depends on batch 1 (`proc.KillPID`), batch 2 (shares `refs.go`/`doc.go` and must land after item 4's engine changes there), and batch 3 (the `buildOptions` `WorktreeRoot` threading must be live before the supervised flip, or batch-mode lookups would anchor a different daemon — item5-batch-worktreeroot-threading). That batch-3 edge is a scheduling constraint, not an import (the engine never imports the CLI); it exists so the prerequisite lands first. Cards are ordered: the shared constant + supervised argv (card 10), then the escalation (card 11, which the flip relies on to make supervised safe to go live), then the flip + docs (card 12). The two `//go:build integration` proofs this work needs — supervised dispatch end-to-end and the `--in-file` resolve end-to-end — live in **batch 5** (which depends on this batch), kept separate so this batch's `verify:` stays a fast untagged run of the decision-logic tests while the integration-tagged edits get a compile-only gate that never spawns gopls (see batch 5 and the `verify-excludes-edited-tagged-test` invariant).

### Card 11: Recover a wedged supervised daemon via re-dial-under-lock then one restart

- **Context:**
  - `internal/proc/proc_linux.go`
  - `internal/codeintelengine/daemonstate.go`
  - `internal/codeintelengine/lspclient.go`
  - `internal/codeintelengine/daemonstate_test.go`
  - `internal/codeintelengine/lspclient_test.go`
- **Edits:**
  - `internal/codeintelengine/ensureserver.go`
  - `internal/codeintelengine/ensureserver_test.go`
  - `internal/codeintelengine/supervised_test.go`
- **Creates:** none
- **Deletes:** none
- **Moves:** none
- **Requirements:** Close the wedged-daemon gap inside `ensureSupervised`'s step-1 reconnect path. Today, when a non-stale recorded state fails dial-or-finalize, the code falls through to the lock/spawn path, which — finding the state still non-stale under the lock (step 3) — merely sleeps and re-loops, so a wedged-but-alive daemon strands every caller forever. Change it so that a dial-or-finalize failure against a **non-stale** state escalates: acquire the spawn lock (reusing the existing `lock.TryAcquireWriteLock` + bounded-poll machinery and the overall `deadline`), then re-read the state and **re-dial the currently-recorded address under the lock** with the same bounded retry the spawner's step 6 uses (10 attempts × 50 ms) followed by `finalizeConnection`. If that fresh under-lock dial+finalize **succeeds**, use that connection and do **not** kill (covers the races where another caller already respawned, or the same daemon recovered between the failed dial and lock acquisition). Only if the fresh dial+finalize **also fails** is the daemon genuinely wedged: call `proc.KillPID(state.PID)` **as a best-effort call** — if the daemon died on its own between the failed re-dial and this call, `KillPID` returns a non-nil error (e.g. `ESRCH`/`ErrProcessDone`); ignore/log that error rather than returning it, since the respawn that follows is exactly the right response to a daemon that is already dead, not just wedged — then remove the stale socket (`os.Remove`, ignoring `os.IsNotExist`), and respawn once via the existing step 4–7 spawn sequence. **Lock release (required):** the escalation acquires the spawn lock, so every one of its return paths must release it before returning, exactly as steps 2/3/4–7 already do — the reuse-success return (`healthy == true`), the deadline-guard `ErrServerSpawnTimeout` return, and the wedged path (which falls through to steps 4–7's existing release). The simplest safe form is a `defer fileLock.Release()` immediately after the escalation acquires the lock, guarding all paths uniformly (drop steps 4–7's explicit release on the escalation path if you take this route, to avoid a double-release); otherwise release explicitly on the reuse-success and deadline-timeout paths and rely on steps 4–7's existing release for the respawn path. A leaked `gofrs/flock` handle stays held for the rest of the process: batch-mode CLI calls invoke `ensureSupervised` once per positional arg in the **same** process (`buildOptions` gives them the same `WorktreeRoot`, hence the same lock), so an unreleased escalation lock wedges every later arg's lookup on `TryAcquireWriteLock` until its own deadline. **Deadline guard (required):** `reconnectUnderLock`'s own dial retry is already inherently bounded (the same finite 10×50ms loop as step 6, ~500ms worst case against an unreachable socket), so the deadline is enforced by an explicit `if time.Now().After(deadline) { return nil, &ErrServerSpawnTimeout{Lang: lang} }` check placed immediately after `reconnectUnderLock` returns `healthy == false` and **before** `proc.KillPID`/respawn (mirroring the existing step-2/step-3 deadline guards). Do not attempt to thread the deadline into the helper's retry itself — the after-return check is what returns `ErrServerSpawnTimeout` when the ~500ms re-dial overshoots the deadline, and is exactly what keeps `TestEnsureSupervised_UncontendedLockWithUndialableHealthyStateReturnsErrServerSpawnTimeout` (300ms) green. Without this guard, a caller whose `deadline` expires during the ~500ms re-dial would fall through to respawn — and with a bogus command (e.g. a test's placeholder) fail at `cmd.Start()`, returning a spawn error instead of `ErrServerSpawnTimeout`. Concretely, `supervised_test.go`'s existing `TestEnsureSupervised_UncontendedLockWithUndialableHealthyStateReturnsErrServerSpawnTimeout` (timeout 300ms, uncontended lock, healthy-but-undialable state) now exercises exactly this escalation path: verify it still returns `ErrServerSpawnTimeout` (the deadline guard fires before any `KillPID`, so the held fixture PID is never killed) within its 5s bound, and update its doc comment — which currently describes the pre-escalation `step1->step3` spin — to state it now drives the re-dial-under-lock escalation to a deadline-bounded `ErrServerSpawnTimeout`. One restart per call, bounded by `deadline`. The spawner's own step-6 first-bind retry is unaffected (it is not a reconnecting caller and never enters this escalation). Keep `daemonStale` unchanged (pure PID + protocol check). This card also makes false `ensureSupervised`'s doc-comment sentence "The daemon this function spawns is never killed by its caller" — update it (and its immediately following "outlives this call" / "only things that ever terminate it" prose) to state that a wedged daemon is now force-killed via `proc.KillPID` by the escalation this card adds, alongside its own idle timeout and stale-socket cleanup as the other ways it can end. Factor the "re-dial-under-lock, reuse-or-restart" decision into a **pure** helper — proposed name and signature `func reconnectUnderLock(ctx context.Context, network, address string, dial func(ctx context.Context, network, address string) (*lspClient, error), finalize func(ctx context.Context, client *lspClient) error) (client *lspClient, healthy bool, err error)` (exact shape is the implementer's, but it must take the dial and finalize steps as injectable function values). It runs the bounded 10×50ms dial retry against the recorded `address` and, on a successful dial, `finalize`; it returns `(client, true, nil)` when the fresh dial+finalize succeeds (reuse — caller must **not** kill) and `(nil, false, nil)` when the dial retries or finalize fail (caller must restart). Crucially, the helper itself performs **no** `KillPID`, spawn, or state I/O — those stay in `ensureSupervised`, which calls `proc.KillPID(state.PID)` + respawn only when the helper returns `healthy == false`. This keeps the helper's tests pure (injected fakes only, no real process). Add `ensureserver_test.go` tests — untagged and **process-free** (fake `dial`/`finalize` closures, no real spawn or kill) — covering: (a) another caller already respawned — injected dial+finalize succeed → `(client, true, nil)`, no restart; (b) same daemon recovered — dial+finalize succeed → `(client, true, nil)`; (c) genuinely wedged — injected dial (or finalize) fails → `(nil, false, nil)`, so the caller would `KillPID`+respawn. Do **not** place any real-process-spawning fixture in `ensureserver_test.go`: it is untagged and is **not** on `cmd/lyx/tierpurity_test.go`'s `allowedSpawners` map (only `supervised_test.go` and `daemonstate_test.go` are file-allowlisted in this package), so a spawn there would pass this batch's `go test ./internal/codeintelengine/...` gate but fail `TestTierPurity_UntaggedTestsSpawnNothing` on the repo-wide `done_gate`. Because the helper is pure, none of (a)/(b)/(c) needs a real PID; if end-to-end coverage of the actual `KillPID`+respawn against a live daemon is ever wanted, it belongs in the already-allowlisted `supervised_test.go` (see its `spawnAndHoldSubprocess` fixture) or the `//go:build integration` suite, never in `ensureserver_test.go`. **Lock-release coverage (`supervised_test.go`, untagged):** prove the escalation's own new return paths free the spawn lock. (1) Extend the existing `TestEnsureSupervised_UncontendedLockWithUndialableHealthyStateReturnsErrServerSpawnTimeout` to assert that after the deadline-timeout return the lock is free — a follow-up `lock.TryAcquireWriteLock(lockPath)` returns `acquired == true` — proving the deadline-timeout path released it. (2) Add a **reuse-success** escalation test that drives the escalation to a successful under-lock re-dial: write a non-stale state (`PID: spawnAndHoldSubprocess(t)` so `daemonStale` is false and, should the escalation ever wrongly take the wedged branch, `KillPID` hits the held fixture — never the test process; `Address: "unix;"+socketPath`; current protocol) and bind an **in-process** fake LSP server on `socketPath` (a `net.Listen("unix", socketPath)` + goroutine responder, following `lspclient_test.go`'s `TestLSPClient_DialTransport_InitializeOverUnixSocket` unix-socket fake-server pattern) that **fails the first accepted connection's `workspace/symbol` probe but answers the second connection's `initialize`+probe successfully** — so step-1's dial-then-`finalizeConnection` fails (triggering the escalation) while the under-lock re-dial+`finalizeConnection` succeeds. Assert `ensureSupervised` returns the reused connection, that the held fixture PID is still alive (no `KillPID`), and that the lock is free afterward (`lock.TryAcquireWriteLock(lockPath)` → `acquired == true`). This drives the reuse-success lock-release path deterministically with no real gopls (the fake server is in-process; the only subprocess is the allowlisted `spawnAndHoldSubprocess` PID fixture).
- **Commit:** `fix(codeintelengine): recover a wedged supervised daemon via re-dial-under-lock then one restart`
