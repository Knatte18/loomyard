One notable implementation decision, flagged since it deviates from the plan's literal text: the plan specifies `assertOverlayBurlerCommitSeams(t *testing.T, r shedbuild.Recipe)`, but I implemented it as `(t testing.TB, r shedbuild.Recipe)`. A concrete `*testing.T`'s real `t.Errorf`/`t.Fatalf` calls unavoidably propagate subtest failure up through every ancestor `Test` function in Go's testing package (verified experimentally) — there is no public API to suppress that. Since the plan's own requirement is that the negative-case subtests "record whether the rule reported a failure... so a case asserting rejection does not fail the outer test," satisfying that literally requires the helper to accept the `testing.TB` interface so a capturing stub (`capturingT`, embedding `testing.TB` and overriding `Errorf`/`Fatalf`/`Helper`) can be substituted for the reject-case runs, while the shipped-recipe positive test still passes a real `*testing.T` (which satisfies `testing.TB`). This keeps `go test ./...` green while still exercising real `t.Errorf` calls on the shipped recipe.
