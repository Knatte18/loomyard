## Findings

### [BLOCKING] Card 6 forward-references Card 7's fetchWithBrowser
**Location:** Batch 1 / Card 6 (fetch.go)
**Issue:** `newFetcher()`, defined in Card 6, wires `browser = fetchWithBrowser`, but `fetchWithBrowser` is defined in Card 7's `browser.go`, which does not exist at Card 6's commit — `go build`/`go test` fails with `undefined: fetchWithBrowser`, contradicting Batch Scope's claim that "intermediate commits compile as far as possible."
**Fix:** Move `newFetcher()` (or at least its `browser` field wiring) into Card 7 alongside `browser.go`; Card 6 defines only `fetcher`/`fetchPage`.

### [BLOCKING] fetchReddit has no injectable HTTP seam but Card 6's tests assume one
**Location:** Batch 1 / Card 5 (reddit.go) and Card 6 (fetch_test.go)
**Issue:** Card 5 specifies `fetchReddit(ctx context.Context, url string)` performing its own internal GET, entirely separate from the `fetcher.httpGet` seam. Card 6's test plan says "a Reddit URL routes through the Reddit path (stub httpGet returning a Reddit .json body)" — stubbing `f.httpGet` has no effect on `fetchReddit`'s own request, so this cascade branch is untestable without a real network call, contradicting the "pure ... no network" requirement.
**Fix:** Give `fetchReddit` an injectable transport too (route it through the `fetcher` seam or a second injected field), consistent with the injection-seam decision.

### [BLOCKING] run.sh always rebuilds under PROWLER_BUILD_ONLY, breaking selftest.sh's own reuse assertion
**Location:** Batch 2 / Card 8 (run.sh) and Card 9 (selftest.sh, test 2)
**Issue:** Step 3's reuse short-circuit ("if BIN exists and is non-empty and PROWLER_BUILD_ONLY is unset, exec") requires PROWLER_BUILD_ONLY unset. Whenever it IS set — every selftest.sh invocation — the wrapper always falls through to steps 4-7 and reruns `go build -o "$BIN"`, changing the binary's mtime each time. Card 9 test 2 asserts "unchanged mtime (reuse path — no rebuild)" across two back-to-back `PROWLER_BUILD_ONLY=1` runs, which this algorithm cannot satisfy — batch 2's `verify:` would fail as specified. (Production runtime, with PROWLER_BUILD_ONLY unset, is unaffected — only the self-test path is broken.)
**Fix:** Make the BIN-exists reuse check independent of PROWLER_BUILD_ONLY; use PROWLER_BUILD_ONLY only to choose exec-vs-exit-0 at the very end.

### [BLOCKING] No test exercises main()'s multi-URL join / per-URL-error behavior
**Location:** Batch 1 / Card 7 (main.go)
**Issue:** discussion.md's Testing section explicitly requires a "Multi-URL join" test ("results joined with `\n\n---\n\n`; per-URL error captured inline without aborting siblings"), but Card 7 places all of this logic directly inside `main()` with no extracted, named function, and creates no `main_test.go`. Batch 1's untagged test set (outfile/htmltext/chrome/reddit/fetch) never covers it, and the excluded integration test only drives `fetchWithBrowser`.
**Fix:** Extract the join/per-URL-fetch orchestration into a testable function (e.g. `runAll(urls []string, f fetcher) (string, error)`) and add a Card 7 unit test for it.

### [BLOCKING] New shell scripts have no `.gitattributes` LF pin
**Location:** Batch 2 / Card 8 (run.sh), Card 9 (selftest.sh)
**Issue:** Verified against `.gitattributes`: every existing shebang/embedded shell script is individually pinned `text eol=lf` (e.g. `internal/fabricengine/post-checkout.sh text eol=lf`) precisely so a Windows checkout's `core.autocrlf` can't corrupt it. No card adds an equivalent entry for the two new prowler scripts, despite Windows-via-git-bash being an explicitly supported, named platform — a CRLF checkout would plausibly break `bash run.sh`/`bash selftest.sh` on the operator's own Windows box.
**Fix:** Add `plugins/prowler/1.0.0/scripts/*.sh text eol=lf` (or per-file entries) to `.gitattributes`, in Card 8 or Card 14.

### [NIT] go.sum "placeholder" strategy contradicts "intermediate commits compile"
**Location:** Batch 1 / Card 1, Batch Scope
**Issue:** Card 1 defers go.sum finalization to Card 7's `go mod tidy`, but go.mod already `require`s chromedp/go-readability/goquery from Card 1 onward; without go.sum entries for those, `go build`/`go test` cannot resolve the module graph, so Cards 1-6 likely fail to build, contradicting Batch Scope's "intermediate commits compile as far as possible."
**Fix:** Either state explicitly that Cards 1-6 are commit-only (not build-verified) until Card 7, or tidy incrementally as each importing card lands.

### [NIT] .gitignore append doesn't account for the mill-managed fence
**Location:** Batch 2 / Card 14
**Issue:** The existing `.gitignore` has a `# === mill-managed (regenerated by mill-setup) ===` … `# === end mill-managed ===` block; Card 14 doesn't say the new `plugins/prowler/1.0.0/bin/` entry must go outside it, risking loss on a future mill-setup regeneration.
**Fix:** State explicitly that the entry is appended after `# === end mill-managed ===`.

## Verdict

REQUEST_CHANGES
Five BLOCKING defects: a cross-card compile-order break, an untestable Reddit fetch seam, a self-test-breaking rebuild bug, missing main() test coverage, and a missing CRLF-safety pin for Windows.
